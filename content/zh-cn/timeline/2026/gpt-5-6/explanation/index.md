## 当时解决了什么问题

2025 年的能力分布是「旗舰有、低档没有」：computer use 只有在最贵的模型上才可用，多 Agent 编排要靠框架自己搭。产品因此要在「能力」和「成本」之间做取舍——想要 computer use，整个产品线的单价就被顶上去。

GPT-5.6 把这两项拉平到全家族：最低成本的 Luna 也支持多 Agent 编排与 computer use，且三档共享约 105 万 token 的上下文。取舍点从**有没有**变成**用哪一档**。

对做平台的意义很直接：**Agent 的默认能力集合被重画了**。如果 computer use 与编排在各档都有，那么运行时要解决的就不是「能不能做」，而是「做得对不对、花了多少、谁批准的」。

## 对后续 LLM 与 Agent 的影响

两周后的 [GPT-6 Astra](../../gpt-6-astra/) 把重点转向「怎么确认自己做完了」，再往后一个月的 [Opus 5](../../opus-5/) 也强调自我验证。**2026 年年中之后，前沿模型的竞争点从「能做什么」转向「做完了怎么知道」**——这正是定义第四条（完成判据）在核心侧的对应物。

**边界**：这是核心能力的下放，不是 Agent 形态的变化。编排是核心提供的原语，循环仍由运行时驱动。
