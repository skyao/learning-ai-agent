## 当时解决了什么问题

2026 年之前，Agent 的身份基本是**借用**的：用你的 OAuth、用你团队的服务账号、或者一把长期 API key。这带来三个问题——审计追不到人、权限只能一次给足、凭证一旦泄露影响面等于整个账号。

CrowdStrike 给的三条规则逐一对应：

| 问题 | 规则 |
| --- | --- |
| 追不到人 | 每个动作**绑定到它代表的人或工作负载** |
| 权限给太足 | **无常设凭证**，令牌按最小权限、最短时间签发 |
| 冒用与共享 | 身份**可加密验证，不可冒用、不可共享** |

注意这是**安全厂商**给出的答案，不是模型厂商——这本身是信号：Agent 身份问题先被当作**终端与凭证安全**问题来处理。

## 与另外两条线的关系

- [Managed Agents](../../managed-agents/) 处理的是**沙箱里的凭证**（token 不进沙箱）；
- [Snowflake](../../snowflake-cortex-agents/) 处理的是**数据侧的授权**（提供方暴露、消费方批准）；
- 这一条处理的是**身份本身**（谁是谁、代表谁、能做什么）。

三条合起来才是完整的 2026 答案：**主体独立于用户，凭证不落执行环境，动作可归因**。

## 对后续 LLM 与 Agent 的影响

最有价值的一处是 **Falcon Guardian 的「影子 Agent」概念**：终端上会出现没人批准过的 Agent。这在 2026 年是真实问题——[OpenClaw](../../openclaw/) 一类自托管 Agent 让每个人都能在自己机器上跑一个，企业需要先**发现**再谈治理。

对做平台的人：**发现与清点是治理的前提**。在能管住之前，先得知道有多少在跑。这条和 [2026 年 Tag 的组织级身份](../../claude-tag/)是同一命题的两端——一个从组织往终端看，一个从终端往频道看。
