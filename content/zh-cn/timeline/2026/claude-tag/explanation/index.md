## 当时解决了什么问题

2025 年的 Claude Code 很强，但是「一个开发者的终端」。团队协作发生在 Slack：任务从对话里冒出来，上下文在频道里，责任不在某一次私人聊天。Tag 把与 Claude Code on the web 相同的短暂沙箱引擎放到频道线程上：委派可见、可旁观、可交接。控制协议没有新发明；生命周期和权限模型有。ambient 把循环从「被叫才动」扩到「跟进未决事项」——主动度上升，误报与越权风险也上升，所以要管理员划频道和工具。

按定义这 **是** Agent：决策、在沙箱与已连接工具里行动、按线程反馈再决策。人在环路变成**多人**在环路。MCP / Skills 在这里变成管理员按 scope 配的 bundle，而不是每人自己的 connector。

## 对后续 LLM 与 Agent 的影响

主矛盾从「会不会写代码」外移到：用谁的权限、记忆跟谁走、沙箱闲了怎么办。次日的 [Agent identity](../../agent-identity/) 把「不要 act as the user」写成公开设计。8 月 3 日旧 Slack 应用切走，是治理事件：身份从每人自己的账号变成组织配的那一个。不要把 Team/Enterprise Beta 写成已经普及；个人计划与第三方部署当时不在范围内。ZDR 与频道记忆互斥，文档已写。A2A 仍偏企业平台叙事；Tag 的多驾驶员是产品层，不是跨厂商互操作。
