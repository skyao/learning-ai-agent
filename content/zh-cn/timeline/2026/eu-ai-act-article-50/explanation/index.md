## 当时解决了什么问题

Agent 在对外交互时的核心身份问题是：**对面那个人知不知道自己在跟机器说话，以及这台机器代表谁**。此前的产品实践全是自选动作——有的在 UI 上标注，有的靠用户自己推断。

第 50 条把它变成义务，而且**明确写进了 Agent 与多 Agent 架构**：设计上就要披露人工性质与委托人。指南的措辞值得注意——它把这条的理由写成「代理与授权的透明度，以及对行动后果的问责」，**关注点是授权链，不是内容真假**。

## 三个要注意的口径

1. **中间步骤不算要标注的合成内容**。推理与思维链、网页请求与浏览器动作都被明确排除。这避免了把 Agent 的内部过程当作「生成给公众的内容」。
2. **「AI agent」不是法律定义**。官方 FAQ 说得很清楚：术语没有法律定义，靠「AI 系统」与「通用模型」两个既有定义覆盖。这是立法技术上的回避——和加州 AB 316 用「自主程度可变的系统」是同一手法。
3. **真正生效的只有这一档**。同一批立法把高风险义务推迟到了 2027 年底与 2028 年。**不要把 2026-08-02 写成「AI Act 全面生效」。**

## 对后续 LLM 与 Agent 的影响

把两个法域并排看，路径差异很清楚：

| | 欧盟第 50 条 | 加州 AB 316 |
| --- | --- | --- |
| 管什么 | 上游：**披露是谁在行动** | 下游：**别拿自主性推责** |
| 生效 | 2026-08-02 | 2026-01-01 |
| 要求 | 设计上披露人工性质与委托人 | 不得以「AI 自主」抗辩 |

两条合起来给平台设计的约束是：**动作要能追溯到委托人**。但两条都没有要求**审计留痕**——「查得清出了什么事」这件事，截至 2026 年 9 月仍是法律空白。这是 [2027 提纲](../../../2027/overview/)最值得继续盯的点之一。
