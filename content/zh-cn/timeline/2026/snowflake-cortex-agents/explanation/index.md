## 当时解决了什么问题

企业数据平台上的 Agent 一直有个尴尬：数据在平台里，环却跑在外面。开发者要自己接鉴权、自己写编排、自己处理长任务的断线——而这些恰恰是平台已经解决过的问题（权限、调度、事务）。

三条 GA 各补一块：**跨应用编排**解决「别人的数据怎么合规地用」，**服务端 loop** 解决「谁托管循环」，**异步 API** 解决「任务比连接活得久」。

权限那条值得单独看：跨应用调用需要**提供方暴露工具 + 消费方批准**，配合角色委派。这是**数据侧的最小权限模型**，与 [CrowdStrike](../../crowdstrike-agent-identity/) 在安全侧的短时令牌、[Managed Agents](../../managed-agents/) 在运行时侧的 scope bundle 是同一个方向的三种实现。

## 对后续 LLM 与 Agent 的影响

这条的意义不在于 Snowflake 做了什么新东西，而在于**做这件事的是数据平台**：

- 2023–2025 年，Agent 运行时由模型厂商与专做运行时的公司提供；
- 2026 年，**掌握数据与权限的企业平台也开始提供**——因为「Agent 能碰什么数据」本来就在它们手里。

对做 Agent 平台的人，这是竞争面的变化：对手不只是其他运行时，还包括**已经持有凭证与数据的既有平台**。它们的优势不在沙箱，而在**它已经知道谁有权访问什么**。
