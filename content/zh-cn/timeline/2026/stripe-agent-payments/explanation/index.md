## 当时解决了什么问题

Agent 开始真的花钱：调模型、租沙箱、买数据。此前这笔账落在开发者身上——预充值、配额、事后对账。麻烦出在两头：**成本产生的速度和收款的速度不匹配**（Agent 以机器速度烧 token），以及**授权不可追溯**（一次会话里谁批了哪笔）。

Stripe 给的两件东西正对这两头：**按 token 实时结算**解决速度差，**一次性虚拟卡 + 逐笔批准**解决授权。

## 最值得记的不是支付，是那张一次性卡

「真实支付信息不暴露给 Agent，每任务一张一次性卡，每笔支付由人批准」——这是**凭证设计**，与同期 [Managed Agents](../../managed-agents/)「凭证不进沙箱」、[Agents SDK](../../agents-sdk-2026/)「凭证与编排不进模型代码环境」是同一个思路的第三种实现：

| 场景 | 凭证处理 |
| --- | --- |
| 代码执行 | token 不进沙箱，harness 不知道凭证 |
| 文件与时序 | 权限映射到 Unix 文件权限 |
| **支付** | **一次性虚拟卡，逐笔人批准** |

三条合起来看，2026 年的一个共同答案浮现了：**Agent 可以行动，但凭证不由它持有。**

## 对后续 LLM 与 Agent 的影响

按定义，这**不是** Agent，也不是执行语义的变化——循环没变，动作接口没变。它改的是**经济语义**：Agent 成为可以独立计量、独立结算的经济参与者，而授权链仍回到人。

对做平台的人有一条实际含义：**成本与权限正在合并成同一个控制面**。谁是 principal、它花了多少、哪一步花的，在 2026 年之后是同一套账。
