## 当时解决了什么问题

2025 年的运行时——[Claude Code](../../../2025/claude-code/)、云端 [Codex](../../../2025/openai-codex/)——把循环装进一个「装上即委派」的产品里，但循环与执行环境是长在一起的：容器死了，会话就没了。对单次开发会话够用；对要跑几小时的异步任务就是硬约束。

这一步把 Agent 拆成三个可替换的接口：**session**（日志）、**harness**（循环）、**sandbox**（执行环境）。拆开之后，容器死亡降级成一次工具调用错误，harness 崩溃可以从事件日志续跑。**「进程一直活着」从正确性前提变成了实现细节**——这是这条线的关键变化。

第二个变化是**凭证边界**：token 不进沙箱、harness 不知道凭证存在。这让「模型生成代码跑在哪儿」与「密钥放在哪儿」第一次成为两个可以分别回答的问题。

第三个变化容易被忽略：**计费单位**。$0.08/session-hour 按 running 状态毫秒计费，是「Agent 运行时按会话时长计价」的首个一手定义——前面 [阿里云 AgentRun](../../../2025/aliyun-agentrun/) 是产品侧的同类主张，但没有给出这么明确的计价语义。

## 对后续 LLM 与 Agent 的影响

把它和同期两家放在一起看，2026 年上半年的架构命题是**同一个**：

| 厂商 | 措辞 | 共同点 |
| --- | --- | --- |
| Anthropic | session / harness / sandbox 三接口 | 控制面与执行面分开 |
| [OpenAI](../../agents-sdk-2026/) | harness / compute separation | 凭证与编排不进模型代码环境 |
| [Google](../../google-ax/) | distributed harness runtime | 从可挂起/恢复的镜像供给执行环境 |

三家独立收敛到同一形状，说明这不是某家的产品选择，而是**长时程 Agent 对执行层的必然要求**。这也解释了为什么 [Claude Tag](../../claude-tag/) 后来能直接把同一套短寿沙箱引擎搬进 Slack——引擎与委派面已经解耦了。

要注意边界：本条讲的是运行时怎么组织，不涉及沙箱内部怎么隔离。后者属于另一条线。
