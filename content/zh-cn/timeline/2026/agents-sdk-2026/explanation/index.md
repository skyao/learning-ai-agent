## 当时解决了什么问题

2025 年的 Agents SDK 是一套编排积木：单/多 Agent、内置工具、tracing，进程是调用方的，跑在哪由开发者自己决定。到 2026 年，长时程任务把「跑在哪」变成了库必须回答的问题——一个跑几小时的 Agent 需要一份能存活的工作区、一套权限、以及容器没了之后能接着来的办法。

这一版的答案是把**环境**收进库的抽象里：Manifest 描述工作区长什么样，沙箱供应商是可换的实现，快照负责续跑。

三点值得单独记：

1. **沙箱变成可插拔依赖**。同一个 Agent 可以今天跑在 Docker 里、明天跑在托管沙箱上——这是 2024-11 [MCP](../../../2024/mcp/) 在工具层的思路，被搬到了执行环境层。
2. **权限映射到 Unix 文件权限**。听起来朴素，但它是「Agent 能碰什么」第一次用操作系统里已有的语义表达，而不是自定义一套。
3. **凭证与编排不进模型代码的环境**。与 [Managed Agents](../../managed-agents/) 同一天前后的说法几乎一致，两家显然在解同一道题。

## 对后续 LLM 与 Agent 的影响

这条与 [Managed Agents](../../managed-agents/)、[Google AX](../../google-ax/) 构成 2026 年上半年的同一件事：**执行环境从开发者的选型变成运行时的抽象**。

区别在于形态：Managed Agents 是托管服务，AX 是自托管运行时，Agents SDK 是库——托管、自托管、库三条路同时存在，且都收敛到「控制面与执行面分开」。这个三分布局本身就是 2026 年供给侧的实况，不该写成某一家的胜利。
