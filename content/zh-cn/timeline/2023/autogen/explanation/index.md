## 论文解决了什么问题

单只 LLM 加工具已经能跑 ReAct。更复杂的任务被拆成「写代码的、跑代码的、盯安全的、补常识的」。若每次都手写控制平面，编排会爆炸。AutoGen 的解法是：每个角色是可对话对象，默认收到消息就回；工作流看起来像聊天，而不是一张显式状态机。控制流从 `while` 变成消息总线：谁在何时对谁说话。

## 对后续 LLM 与 Agent 的影响

工程化：2023 年「多 Agent」从口号变成可 clone 的库。后来许多图/角色框架仍是消息传递加自动回复。按 AI Agent 定义，多只 LLM 互相对话，**至少一方**在对环境行动（执行代码、调函数），整体才是 Agent 系统；若只产文本，就还是角色扮演。总线本身不产生副作用。

限度：角色变多会放大空转和串通式幻觉；论文自己把代码执行写成风险。它是开发库，循环仍在你的进程里。不要把它读成已经解决了 SWE-bench 那种真实仓库修改。消息条数 ≠ 完成率；多角色 ≠ 更可靠的单步。
