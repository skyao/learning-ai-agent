## 这个产品解决了什么问题

[Codex](../../codex/) 证明模型能够写出通过单元测试的函数。日常开发的需求更窄：**光标已在文件里，下一行或下一个函数是什么。** Copilot 把这一步收缩为编辑器内的建议。产品没有引入新的学习算法，它发明的是交付位置：VS Code 光标处、可以循环的候选、由人决定是否接受。技术预览选择 Python、JavaScript、TypeScript、Ruby、Go，是因为当时在这些语言上的生成更稳定。

人在环路是产品定义的一部分，不是缺陷描述。失败由人修改提示或手写。按 AI Agent 定义，这不是 Agent。

## 对后续 LLM 的影响

代码模型第一次有了大规模日活界面。反馈（接受或拒绝）后来成为改进补全的产品数据，接口从 2021 年 6 月起就已存在。「提示」变成了当前文件：GPT-3 的 few-shot 是刻意拼接的示范，Copilot 的条件则是打开的缓冲区、注释与函数名。上下文学习从论文里的实验设定变成默认的 IDE 行为。

「Copilot」一词自此被占住。此后 Microsoft 365 Copilot、GitHub Copilot Chat 以及各种「X Copilot」都借用副驾驶隐喻。2021 年这个词所指的仍是补全，不是自主执行。

## 对 AI Agent 的影响

时间线把它标成底层能力里的**工程化**：有副作用，无目标循环。演化写在交付位置的变化上，不把 2023 年的形态写回 2021 年。

| 2021 技术预览 | 后来编码 Agent 多出来的能力 |
| --- | --- |
| 当前文件上下文 | 仓库、终端、浏览器、issue |
| 建议一行 / 一个函数 | 多文件补丁、命令、测试 |
| 人立刻接受或拒绝 | 循环中依据测试回执再修改 |
| 无自主目标 | 有任务目标（修复缺陷、实现规格） |

副作用发生在编辑器缓冲区：插入或替换文本。观察等于当前缓冲区。没有「做到某个外部谓词为真」的终止条件。它不是 Agent，但是「Copilot → Agent」这条产品线的起点。
