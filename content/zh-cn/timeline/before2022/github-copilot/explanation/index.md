## 这个产品解决了什么问题

Codex 论文解决的是「模型会不会写出能过单测的函数」。日常开发的问题更窄也更具体：**光标已经在文件里，下一行或下一个函数是什么。** 人若去网上搜，要改检索词、离开编辑器、再粘贴回来。Copilot 把这一步收成编辑器内的建议。

它依赖的前提是 Codex 已经能从周围代码与注释做条件生成。产品没有发明新的学习算法；它发明的是**交付位置**：VS Code 光标处、可循环的候选、人决定接受。技术预览选 Python / JS / TS / Ruby / Go，是因为这些语言上生成当时更稳，不是因为它们更「Agent」。

人在循环不是缺陷描述，是产品定义。没有自主目标，没有多步环境循环，失败了由人改提示或手写。按 AI Agent 定义，这不是 Agent。

## 对后续 LLM 的影响

- **代码模型第一次有大规模日活界面。** API 私有测试是给开发者搭应用；Copilot 是给写代码的人直接用。反馈（接受 / 拒绝建议）后来成为改进补全的产品数据，这条闭环不属于 2021-06 公告，但接口从那天起就在。
- **「提示」变成当前文件。** GPT-3 的 few-shot 是刻意拼的示范；Copilot 的条件是打开的缓冲区、注释、函数名。上下文学习从论文设定变成默认 IDE 行为。
- **Copilot 一词被占住。** 之后 Microsoft 365 Copilot、GitHub Copilot Chat、各种「X Copilot」都借用结对/副驾驶隐喻。2021 年的所指仍是补全，不是自主执行。

## 对 AI Agent 的影响

时间线把它标成底层能力里的**工程化**：不是 Agent，但是「Copilot → Agent」的起点。演化可以明确写在交付位置的变化上，而不把 2023 写回 2021：

| 2021 技术预览 | 后来编码 Agent 多出来的东西 |
| --- | --- |
| 当前文件上下文 | 仓库、终端、浏览器、issue |
| 建议一行 / 一个函数 | 多文件补丁、命令、测试 |
| 人立刻接受或拒绝 | 循环里根据测试回执再改 |
| 无自主目标 | 有任务目标（修 bug、实现规格） |

它仍然不是 Agent：建议出现在光标处，由人决定是否采纳。
