原文：[Fikes & Nilsson, 1971](https://ai.stanford.edu/~nilsson/OnlinePubs-Nils/PublishedPapers/strips.pdf)，*STRIPS: A New Approach to the Application of Theorem Proving to Problem Solving*，*Artificial Intelligence* 2: 189–208。IJCAI-71 报告，实现用 LISP 跑在 PDP-10 上，服务于 SRI 的机器人研究（Shakey）。

## 这个概念是什么

STRIPS（Stanford Research Institute Problem Solver）是一个**符号规划器**。它要回答的问题是：给定对当前世界的描述、一组可以执行的动作、以及一个目标条件，找出一串动作，使得执行之后目标成立。

它处理的不是自然语言，也不是从数据里学到的策略。世界被写成一阶谓词演算中的合式公式（wff）；每个动作对应一个算子，算子会增删公式；计划就是算子的有序列表。机器人真正去推箱子、走过门，是计划生成之后由执行程序完成的事。论文明确区分两件事：对世界模型**应用算子**发生在规划阶段；**执行动作例程**才改变物理世界。

在经典人工智能里，这一支通常称为 **planning**（规划）。1998 年以后的 PDDL（Planning Domain Definition Language）把 STRIPS 风格的领域写成标准输入，仍是同一条技术路线。

## 论文的主要内容

### 要解决的问题

作者把 STRIPS 放进一类问题求解器：在「世界模型」的空间里搜索，直到找到一个能满足目标的模型。对任意世界模型，都存在一组可应用的算子，每个算子把该模型变成另一个模型。求解器的任务是找到算子的复合，把初始模型变成满足目标的模型。

他们关心的是机器人重排物体、在房间之间导航这类任务。与棋类、谜题不同，机器人世界必须容纳大量事实：机器人位置、物体位置与属性、可通行空间、边界。因此世界模型不能只用矩阵或表，而要用一阶谓词演算的公式集合。

直接前驱是 Green 的系统：把「找动作序列」也完全交给形式定理证明。作者指出，这条路会被**框架问题**（frame problem）卡住——必须显式说明「这个动作*没有*改变哪些事实」，问题规模上去之后无法实用。STRIPS 的方法是把两件事拆开：

- **定理证明**只在一个固定的世界模型内部进行，用来回答「某个算子现在能不能用」「目标现在成不成立」。
- **在世界模型之间搜索**用类似 GPS 的手段—目的分析（means-ends analysis），用来挑选下一个相关算子。

### 问题空间的三个要素

论文第 2.1 节把问题空间定义为三元组：

1. **初始世界模型** \(M_0\)：一组 wff。例如机器人在位置 \(a\)、箱子 B、C 分别在 \(b\)、\(c\)：

   ```text
   ATR(a)
   AT(B, b)
   AT(C, c)
   ```

   也可以写入一般规则，例如「一个物体不能同时在两个不同位置」。

2. **算子**：按族写成**模式**（schema）。例如 `goto(m, n)` 表示从地板上一点 \(m\) 走到 \(n\)；\(m, n\) 是参数，代入具体常量后才得到一个可应用的算子实例。每个算子描述包含：

   - **前提（precondition）**：一个 wff 模式。要从当前模型证明它的某个实例，算子才能用。
   - **效果**：必须**加入**模型的公式列表，以及不再为真、必须**删除**的公式列表。

3. **目标** \(G_0\)：一个 wff。例如「把箱子 B 和 C 都弄到位置 \(a\)」写成 `AT(B, a) ∧ AT(C, a)`。

当某个世界模型能够证明目标公式时，问题求解结束。

### 搜索策略：手段—目的分析

若对每个模型盲目应用全部可用算子，后继树会大到无法用。STRIPS 采用 GPS 策略：

1. 用定理证明器尝试从当前模型 \(M\) 证明当前目标 \(G\)。
2. 若证明成功，这一层目标完成。若失败，把**未完成的证明**当作 \(M\) 与 \(G\) 之间的**差**（difference）。
3. 寻找效果能够推进该证明的**相关算子**；其前提成为子目标。
4. 对子目标重复同一过程。子目标在当前模型中可证时，应用对应算子，得到新模型，再回头考虑原来的目标。

论文用一个极简例子说明。目标是 `ATR(b)`（机器人到 \(b\)）。若它现在不在 \(b\)，证明失败。算子实例 `goto(m, b)` 相关，因为它的效果能补上这条证明。于是子目标是前提 `ATR(m)`。若初始模型含 `ATR(a)`，则 `ATR(a)` 可证，应用 `goto(a, b)` 得到新模型，其中 `ATR(b)` 成立，求解结束。

搜索树的每个节点是 \(\langle\)世界模型, 目标表\(\rangle\)。相关算子被选出时，并不预先知道它会排在最终计划的第几步：它可能作用在初始模型上（成为第一步），也可能其效果直接蕴含目标（成为最后一步），或落在中间。作者认为这种策略同时吸收了从初始模型向前搜、和从目标向后搜的优点。

实现上，STRIPS 在一个模型内部调用基于归结的定理证明器（与 QA3 同类）来处理带参数的 wff 模式；在模型之间则维护上述搜索树。论文后半给出在房间中行走、推箱子等机器人任务的实例。

### 作者标明的限度

- 规划与执行分离：算子应用改变的是**模型**；物理动作由独立的执行与监控模块负责（文中指向 Munson、Fikes 的相关工作）。
- 框架问题并未从哲学上消失，而是用增删列表把「未列出的公式保持不变」写成操作约定。后来文献称此为 STRIPS 假设。
- 世界必须能被写成谓词；开放文本、传感器噪声、未建模的副作用不在该问题空间内。

## 关键术语

| 术语 | 在这篇论文里的含义 |
| --- | --- |
| 世界模型 | 一阶谓词演算公式的集合，描述某一时刻的世界 |
| 算子 / 算子模式 | 动作在模型上的对应物；模式含参数，实例化后才能应用 |
| 前提 | 应用算子前必须从当前模型证明的条件 |
| 增列表 / 删列表 | 应用算子后加入、删除的公式；未列出的公式默认不变 |
| 计划 | 从初始模型走到目标可证模型的算子序列 |
| 差 | 当前模型无法完成目标证明时，未完成证明所代表的缺口 |
| 框架问题 | 如何简洁地表示「动作不改变哪些事实」 |

## 和 AI Agent 的关系

本笔记要学的 LLM Agent 仍然在做「给定目标，选择动作，使环境朝目标变化」。差别在决策程序：STRIPS 用定理证明加搜索；LLM Agent 用语言模型在多步循环里生成下一步动作。世界的表示也不同：前者是谓词集合，后者是工具回执、文件、屏幕等观察。

因此 STRIPS 是规划问题的经典表述，不是 LLM Agent 的实现祖先。
