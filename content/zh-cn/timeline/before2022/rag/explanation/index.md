## 论文解决了什么问题

2020 年 5 月，与 [GPT-3](../../gpt-3/) 几乎同时。预训练已能把事实压进参数；REALM / DPR 已能检索再抽取。并排三条缺口：参数知识难改、难查、会幻觉；可微检索当时主要服务抽取式阅读，答案必须是原文跨度；生成模型还是闭卷的，知识密集型生成落后。

RAG 的回答是配方，不是新骨干：检索器用现成 DPR，生成器用现成 BART，检索文档当潜变量，用答案似然端到端微调查询编码器与生成器。索引固定、可热替换。生成不必等于抽取。测量终点是开域 QA 与若干生成 / 分类基准，不是「模型自己决定何时再搜一次」。

## 对后续 LLM 的影响

口语里的 RAG 更宽：任意「先搜一段再塞进提示」。论文更窄：参数记忆 vs 非参数记忆写成一对可替换组件。出处绑定在被检索段落上，是后来「带引用作答」的结构前身；[WebGPT](../../webgpt/) 把引用收成浏览动作。换维基索引就能改「谁是总统」——产品里换向量库，走同一条物理路径。

关键限度：**仍是一次前向。** 检索 → 拼接 → 生成。没有「看完回执再决定搜不搜」的外循环。训练要微调，不是 GPT-3 那种纯上下文学习。2023 年以后企业知识库助手沿用了这个名字；实现常常换成「嵌入 + 提示拼接」，不再做论文里的 token 级边际化。

## 对 AI Agent 的影响

有外部知识的 Agent 几乎都先经过「生成之前先检索」。RAG 提供的是这条路径的**单次形态**：外部知识以检索段落进入上下文，决策核心仍是一次生成。它补的是 GPT-3 窗口装不下、权重改不了的那一块，不是循环本身。

| 论文里的机制 | 后来在 Agent 里对应的物理事实 |
| --- | --- |
| 非参数索引（原文块） | 工具回执、代码库、文档可以先被检索再进窗口 |
| 索引热替换 | 不必为每份新知识微调；换库即换记忆 |
| 生成条件于 \(z\) | 当前观察里出现「检索到的证据」；证据选错仍会错 |
| 一次检索 + 一次生成 | 流水线。Agent 循环要的是根据回执再决定下一步（再搜、换查询、放弃） |
| 不用检索监督也能微调 | 后来许多系统连这步微调也省掉，只把结果拼进提示 |

时间线标成底层能力里的**工程化**。它仍然不是 Agent。一次调用答完一道开域题；没有多步环境循环，也没有工具接口协议。
