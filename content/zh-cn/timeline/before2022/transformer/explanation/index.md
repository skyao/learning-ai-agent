## 论文解决了什么问题

2017 年的对象是**序列转换**，主场是机器翻译。编码器—解码器与注意力已是常规附件，主干仍是 RNN（或卷积）。障碍三条，绑在一起：样本内顺序计算无法并行；任意两位置之间的路径随长度线性增长，长程依赖难学；注意力还接在循环网上，不是转换模型的默认计算。

解法是换计算图：缩放点积自注意力让每个位置一步看见全序列（路径 \(O(1)\)，层内顺序操作 \(O(1)\)）；多头避免单次平均抹掉子空间；位置编码补上被拿掉的词序归纳偏置；解码器自注意力加掩码以保持自回归。翻译分数是结果。被改写的是「一层如何表示一段序列」。

论文没有把自身写成语言模型骨架，也没有工具、循环或停机。结论里的下一步是其他模态、局部注意力、以及让生成少一点顺序化。

## 对后续 LLM 的影响

后来能把深度、宽度和数据同时做大，靠的是第 4 节复杂度表允许的训练方式：**层内可并行，任意两 token 一条短路径。** GPT 只用解码器栈；BERT 主要用编码器栈。原论文是完整编码器—解码器。

位置必须另加：正弦、可学习嵌入、相对位置、RoPE，都在回答第 3.5 节同一问题。\(O(n^{2})\) 写在表 1：窗口是物理上限，能并行不等于能无限加长。\(1/\sqrt{d_k}\) 在模型变宽之后仍然在。

GPT-3 的上下文学习、Codex 的代码生成，用的都是这副骨架上的解码器语言模型。它们不是这篇的实验，但都预设了这篇改过的计算图。

## 对 AI Agent 的影响

AI Agent 要的决策核心能读一段开放文本并生成下一步。Transformer 提供**表示与自回归生成结构**，不是策略循环。一次前向是在已有 token 上预测后续 token。

| 论文里的机制 | 后来在 Agent 里对应的物理事实 |
| --- | --- |
| 自注意力一步连接全序列 | 当前观察可以整段进上下文 |
| 掩码自注意力、自回归 | 下一步以文本（或后来的工具调用）逐 token 生成 |
| \(O(n^{2})\) 与有限窗口 | 一次循环能塞进的回执有上限；满了就截断、检索或外挂记忆 |
| 位置编码 | 「第几步、哪一段」对模型不是免费的 |
| 训练可并行、模型可做大 | 核的能力随规模上升；2022 年 CoT「要够大才有用」，前提是这种结构 |

时间线标成底层能力里的**范式更替**：没有可扩展的条件生成器，后面没有可讨论的 LLM 核。它仍然不是 Agent。不含工具接口，不含终止条件，不含对环境的行动环。
