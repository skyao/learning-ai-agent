## 论文解决了什么问题

2017 年的对象是**序列转换**，主要战场是机器翻译。编码器—解码器与注意力已经是常规附件，主干仍是 RNN（或卷积）。三条障碍绑在一起：样本内的顺序计算无法并行；任意两个位置之间的路径随长度线性增长，长程依赖难以学习；注意力仍接在循环网络上，不是转换模型的默认计算。

解法是更换计算图：缩放点积自注意力让每个位置一步看到全序列（路径 \(O(1)\)，层内顺序操作 \(O(1)\)）；多头注意力避免单次平均抹掉子空间；位置编码补回被移除的词序归纳偏置；解码器自注意力加掩码以保持自回归。翻译分数是结果。被改写的是「一层如何表示一段序列」这一层机制。

论文没有把自身写成语言模型骨架，也没有工具、循环或停机。结论中指出的下一步是其他模态、局部注意力，以及让生成少一点顺序化。

### 关键术语：编码器与解码器

论文里的编码器与解码器，与今天 LLM 里被叫做「编码器」「解码器」的东西同名同源，但不是同一件事。区分有两条判据：**有没有交叉注意力，注意力带不带因果掩码。**

论文里两个组件的差别只在一层：

| | 编码器 | 解码器 |
| --- | --- | --- |
| 每层子层数 | 2 | 3 |
| 子层 | 自注意力、前馈 | 因果自注意力、交叉注意力、前馈 |
| 能看哪儿 | 全序列，双向 | 自己只看之前的位置，交叉注意力看编码器全部输出 |
| 生成 | 不生成 | 自回归，一次一个 token |

关键是第三个子层。交叉注意力读的是编码器的输出，解码器每一步都回看源序列的表示——这才是「解码」二字的由来：把已经读进来的表示，逐个符号地解出来。

今天被叫做「编码器」「解码器」的有三样，用法并不相同。

**编码器栈**（BERT 一类）：双向自注意力加前馈，两个子层，没有因果掩码，也不生成。它把整段文本读成一个表示。

**解码器栈**（GPT 一类）：因果自注意力加前馈，**也是两个子层**，与 BERT 的层同为两层，区别只在掩码；**交叉注意力被去掉了**，因为没有编码器可供交叉注意。所以「GPT 只用解码器栈」是准确的，但不能读成「留了解码器、藏了编码器」——去掉第三个子层之后，解码器退化为带因果掩码的自注意力加前馈，名字留了下来，机制回到同一条流上。

**多模态编码器**（图像、语音）：把别的模态投到 LLM 能读的输入空间里。它与论文里那个读源句子的编码器不是一回事，只是沿用了「先编码成表示」的思路。

另有一个同名而无关的用法：tokenizer 的 `encode` / `decode`，把字符串转成 token id 再转回来，与模型结构无关。

对后面的影响落在一处：决策核心是解码器栈，没有编码器，就没有一份「源序列表示」可以被反复交叉注意。上下文里的所有东西都是同一条流上的 token，当前观察、工具回执与历史对话彼此没有结构上的区分，只有位置与文字的差别。

## 对后续 LLM 的影响

后来能够把深度、宽度与数据同时做大，依靠的是第 4 节复杂度表所允许的训练方式：**层内可并行，任意两个 token 之间只有一条短路径。** GPT 只用解码器栈，BERT 主要用编码器栈；原论文是完整的编码器—解码器结构。

位置信息必须另行加入：正弦编码、可学习嵌入、相对位置、RoPE，都在回答第 3.5 节同一个问题。\(O(n^{2})\) 写在表 1 中：窗口是物理上限，能够并行不等于能够无限加长。模型变宽之后，\(1/\sqrt{d_k}\) 仍然在。

GPT-3 的上下文学习与 Codex 的代码生成，用的都是这副骨架上训练出的解码器语言模型。它们不是这篇论文的实验内容，但都预设了这篇论文改过的计算图。

## 对 AI Agent 的影响

AI Agent 需要的决策核心，要能读一段开放文本并生成下一步。Transformer 提供的是**表示与自回归生成结构**，不是策略循环。一次前向计算，是在已有 token 上预测后续 token。

| 论文里的机制 | 后来在 Agent 里对应的物理事实 |
| --- | --- |
| 自注意力一步连接全序列 | 当前观察可以整段进入上下文 |
| 掩码自注意力、自回归 | 下一步以文本（或后来的工具调用）逐 token 生成 |
| \(O(n^{2})\) 与有限窗口 | 一次循环能够容纳的回执有上限；超出后只能截断、检索或外挂记忆 |
| 位置编码 | 「第几步、哪一段」对模型而言不是免费的 |
| 训练可并行、模型可做大 | 核心的能力随规模上升；2022 年 CoT「规模足够大才有效」，前提正是这种结构 |

时间线把它标成底层能力里的**范式更替**：没有可扩展的条件生成器，后面就没有可讨论的 LLM 核心。
