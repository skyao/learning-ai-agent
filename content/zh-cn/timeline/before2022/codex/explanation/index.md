## 论文解决了什么问题

2021 年中，[GPT-3](../../gpt-3/) 已证明规模带来上下文学习，写代码仍是附属现象：GPT-3 在 HumanEval 上约 0%。BLEU 分不清「写得像」和「跑得对」。程序合成要的是**功能正确**。

Codex 做了两件后来被当成默认的事：在公开代码上继续训 GPT，把下一个 token 对准源代码分布；用手写题目 + 单测定义对错，并给出无偏的 pass@\(k\)。手写是为了减少训练语料泄漏。多采样被写成对「试几种写法」的近似。限度写得很硬：长操作链指数变差、会编不存在的符号、会建议不安全配置。沙箱是为了安全地跑这些样本，不是给 Agent 用的执行环境产品。

对象是函数级合成，不是在仓库里改 bug、开 PR。164 道题、平均 7.7 个测试，尺度故意很小，为的是可复现。

## 对后续 LLM 的影响

代码成为语言模型的一等模态。之后 GPT-3.5 / GPT-4 / Claude 把代码能力做进基座，不再单独叫 Codex。评测从像不像变成过不过：HumanEval、MBPP、LiveCodeBench 沿用功能正确。pass@\(k\) 也解释了产品里常见「再生成一次」。文档字符串 ↔ 代码是同一套补全。泄漏与手写基准这个问题，一直传到 SWE-bench 的去污染讨论。

它没有解决指令跟随是否稳定，也没有解决「在真实代码库里定位、修改、验证」——那是 2023–2024 编码 Agent 的评测对象。

## 对 AI Agent 的影响

编码 Agent 的前提是：决策核心能写出**可执行**的代码，并且有办法知道写得对不对。Codex 提供模型侧首证；尺子见 [HumanEval](../../humaneval/)。没有能跑的代码，后来就没有「让模型在仓库里把测试跑绿」的循环。核不是运行时：一次补全一个函数，人在 IDE 里接受或拒绝。

| 论文里的机制 | 后来在 Agent 里对应的物理事实 |
| --- | --- |
| 文档字符串条件生成 | 任务说明、issue、测试名可以当提示；模型吐出补丁或脚本 |
| 单测定义正确 | 循环里「行动」的反馈可以是测试退出码 |
| pass@\(k\) / 多采样 | 同一步可以试多种补丁；后来的重试、best-of-n 是同一逻辑放大到仓库 |
| gVisor 沙箱 | 为评测而隔离；2023 之后沙箱变成 Agent 基础设施，对象从「跑 164 题」变成「别在用户机器上乱执行」 |
| 函数级、独立文件 | 远窄于 SWE-bench / 多文件重构。HumanEval 绿不代表能修真实 issue |

时间线标成底层能力里的**首证**。它仍然不是 Agent：无自主目标，无多步环境循环。
