## 论文解决了什么问题

2020 年卡住的是适应方式：架构已与任务无关，BERT / GPT-2 已证明预训练有效，**每个新任务仍要大规模标注并更新权重。** 任务太多；窄分布微调吃虚假相关；人并不这样学。GPT-2 已把示范写进上下文，分数离微调仍远。要检验的假设只有一句：上下文学习是不是会随规模变强。

主干仍是 GPT-2 式解码器。实验设计改了两刀：zero / one / few-shot 分开测，权重一律不动，把「提示」变成可测量设定；规模做成自变量，1.25 亿到 1750 亿共 8 档。多数任务上 few-shot 随规模上升得比 zero-shot 更陡。翻译、闭卷问答、算术是这条假设的测量，不是终点。被改写的是任务接口：从改权重，变成改这段作为条件的文本。

论文没有工具循环。第 5 节自己标出缺口：有用的系统最终也许该被想成在采取有目标的行动。那是作者留下的空位，不是后人为它补的功能。

## 对后续 LLM 的影响

任务接口从数据集变成上下文里的字符串。few-shot 把示范和待补全拼成一段条件——后来的系统提示、角色句、工具说明，都是同一接口上的用法。一个基座、许多下游，不必为每个任务存一份微调权重。InstructGPT / ChatGPT 改的是指令跟随，不取消这条接口。

窗口是工作集上限：文中 \(K\) 取 10–100，因为 \(n_{\mathrm{ctx}}=2048\)。后来做到 8k、32k、100k+，是在放宽同一条约束。规模是条件不是装饰：同样的提示，小模型用不上。评测污染在第 4 节已经写成方法学问题。

它仍然是补全模型。听话的对话形态是 2022 年 InstructGPT / ChatGPT 才送到大众面前的。

## 对 AI Agent 的影响

决策核心必须在**不重新训练**的前提下，读懂这一轮塞进来的指令、工具回执、失败原因，并生成下一步。GPT-3 测到的正是「新信息写进上下文就能改行为」。Transformer 提供计算图；GPT-3 提供**推理时的适应方式**。Agent 把 Observation 当作工作集，用的是同一机制。

| 论文里的机制 | 后来在 Agent 里对应的物理事实 |
| --- | --- |
| in-context learning，权重不动 | 观察、工具 JSON、摘录当「这一步的条件」，不必为每个环境训一个模型 |
| \(n_{\mathrm{ctx}}=2048\) | 一次循环能看见的回执有上限；满了就截断、检索或外挂记忆 |
| zero-shot 只有自然语言说明 | 后来的系统提示；当时弱于 few-shot，指令跟随不稳 |
| 外环预训练 / 内环上下文 | 慢学习在权重里，快适应在这一次前向。Agent 循环用的是内环 |
| 第 5 节：助手应是有目标的行动 | 作者把缺口留给「行动」；工具循环、ReAct、Function Calling 是后来接的，不是这篇已经做了 |

时间线标成底层能力里的**首证**。它仍然不是 Agent。一次前向预测后续 token；没有对环境的行动环；工作集约 2k。
