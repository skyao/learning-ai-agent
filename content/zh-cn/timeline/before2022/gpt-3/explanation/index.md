模型表、数据配比与实验数字见 [论文](../paper/)。本页只讲：它针对的是什么问题，以及这些问题后来怎样进入大语言模型和 AI Agent。

## 论文解决了什么问题

2020 年的对象是 **NLP 的适应方式**，不是对话产品，也不是 Agent。Transformer 已经把架构变成与任务无关；BERT / GPT-2 已经证明「先预训练再迁移」有效。仍卡住的是最后一刀：**每个新任务仍要准备大规模标注，并更新权重。**

正文第 1 节把这刀写成三件事叠在一起：任务太多，不可能每个都做监督数据；大模型在窄分布上微调容易吃虚假相关；人并不这样学——一句指令或几个示范往往就够。GPT-2 已经把示范写进上下文（当时常被含糊地叫 zero-shot transfer），但分数离微调很远。所以这篇论文要检验的假设很具体：**上下文学习是不是一种会随规模变强的能力。**

它给出的解法不是新结构（主干仍是 GPT-2 式解码器，只加了部分稀疏注意力），而是两件被写进实验设计的事：

1. **把三种推理设定分开。** zero-shot 只有自然语言说明；one-shot 一个例子；few-shot 把窗口（2048 token）里能放下的例子都放进去。权重一律不更新。这把「提示」从一种演示，变成可测量的学习设定。
2. **把规模做成自变量。** 从 1.25 亿到 1750 亿共 8 档，同一套数据训 3000 亿 token。多数任务上，few-shot 随规模上升得比 zero-shot 更陡——更大的模型更会用上下文里的信息。

翻译分数、闭卷问答、算术、人类难以区分的新闻稿，都是这条假设的测量，不是论文的终点。结构上被改写的，是「一个已经训好的模型，怎样接到一个新任务上」：从改权重，变成改这段作为条件的文本。

论文没有声称自己是 Agent，也没有做工具循环。第 5 节反而写明限度：任务仍被拧成预测下一个 token；有用的系统（文中举虚拟助手）最终也许该被想成在采取有目标的行动。那是作者自己标出的缺口，不是后人为它补的功能。

## 对后续 LLM 的影响

影响不在 1750 亿这个数字本身，而在 **任务接口从数据集变成了上下文里的字符串。**

几条后来成为默认、但论文里已经写明的机制：

- **提示即程序。** few-shot 把 \(K\) 个示范和待补全的上下文拼成一段条件。后来的 prompt engineering、系统消息、把说明写成「你是某某」的角色句，都是同一接口上的用法，不是另一种学习算法。
- **不改权重也能换任务。** 这使「一个基座、许多下游」在产品上变得可部署：不必为每个任务存一份微调后的权重。InstructGPT / ChatGPT 后来用人类反馈改的是指令跟随，不是取消这条接口。
- **窗口是物理上限。** 文中 \(K\) 取 10–100，是因为 \(n_{\mathrm{ctx}}=2048\)。能放进上下文的示范、说明、已生成文本，加在一起不能超过这个长度。后来把窗口做到 8k、32k、100k+，是在放宽同一条约束，不是取消它。
- **规模是上下文学习的条件，不是装饰。** 13B 与 175B 在算术、字母操作、SAT 类比上的跳跃，写的是：同样的提示格式，小模型用不上。2022 年思维链「要够大才稳定」，与这条观察同类。
- **污染与评测。** 第 4 节把「训练集里可能已有测试题」写成方法学问题。之后所有在网页上预训练的模型，评测时都要面对同一问题。

没有 GPT-3 这种「提示即可用」的测量，2020 年以后把语言模型当通用接口（API、playground、再后来的对话产品）缺少第一块经验证据。它仍然是补全模型：输入一段文本，预测后面。听话的对话形态是 [2022](../../../2022/) 的 InstructGPT / ChatGPT 才送到大众面前的。

## 对 AI Agent 的影响

本笔记里的 AI Agent 要求：语言模型担任决策核心，在多步循环里行动并依据反馈再决策。决策核心必须能在**不重新训练**的前提下，读懂当前这一轮塞进来的东西——指令、工具回执、文件片段、上一步失败原因——并生成下一步。GPT-3 测量到的，正是这种「把新信息写进上下文就能改行为」的能力。Transformer 提供计算图；GPT-3 提供**推理时的适应方式**。

对应关系钉在论文已写出的机制上：

| 论文里的机制 | 后来在 Agent 里对应的物理事实 |
| --- | --- |
| in-context learning：示范写进上下文，权重不动 | 当前观察、工具 JSON、网页摘录可以当「这一步的条件」，不必为每个环境训一个模型 |
| \(n_{\mathrm{ctx}}=2048\)，few-shot 的 \(K\) 受窗口限制 | 一次循环能看见的回执有上限；窗口满了就要截断、检索或外挂记忆 |
| zero-shot 只有自然语言说明 | 后来的「系统提示 / 任务说明书」；当时这条路径弱于 few-shot，指令跟随还不稳 |
| 外环预训练 / 内环上下文 | 慢学习在权重里，快适应在这一次前向里。Agent 循环用的是内环 |
| 第 5 节：助手最终应是有目标的行动，而不只是预测 | 作者自己把缺口留给「行动」；工具循环、ReAct、Function Calling 是后年来接这个缺口，不是这篇论文已经做了 |

因此时间线把它标成底层能力里的**首证**：上下文学习成立之后，才谈得上把「当前观察」当工作记忆。它仍然不是 Agent。一次前向是在已有 token 上预测后续 token；没有对环境的行动循环，窗口也只有约 2k。那些是 2021 年 WebGPT 的实验室形态、2022 年的对话接口与思维链、2023 年的 ReAct 才接到这段上下文外面的东西。

读完应能分开两句话：GPT-3 解决的是「新任务不必微调」；AI Agent 后来把同一段上下文当成循环里的工作记忆。把第一句写成第二句，属于事后归因。同一年稍后的 [RAG](../../RAG/) 是另一条补窗口的路：生成之前先检索。两者都还是单次或短链流水线。
