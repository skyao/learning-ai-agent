## 论文解决了什么问题

2020 年 5 月，和 [GPT-3](../../gpt-3/) 几乎同时。对象不是对话，也不是 Agent。预训练模型已经能把事实塞进参数（闭卷 QA、T5），REALM / DPR 已经能检索再抽取。仍并排的三条缺口：

1. **参数里的知识难改、难查、会幻觉。** 世界一变就要重训；预测没有出处。
2. **可微检索当时主要服务抽取式阅读。** 答案必须是文档里的一段原文。
3. **生成模型还是闭卷的。** BART / T5 把一切压进权重，知识密集型生成（要写完整句子、要具体、要可核）落后。

RAG 的回答是配方，不是新骨干：检索器用现成的 DPR，生成器用现成的 BART，把检索文档当潜变量，用答案的似然端到端微调查询编码器与生成器。索引固定、可热替换。生成不必等于抽取——文档里没有答案原文时仍可能写对。论文测量的终点是开域 QA 与若干生成 / 分类基准，不是「模型自己决定何时再搜一次」。

## 对后续 LLM 的影响

后来口语里的 RAG 往往比这篇更宽：任意「先搜一段再塞进提示」。论文里更窄，也更具体：

- **参数记忆 vs 非参数记忆** 被写成一对可替换的组件。GPT-3 把知识主要放进权重；RAG 证明生成侧也可以外挂一份可读、可改的记忆。
- **出处。** 生成条件于被检索的段落，预测可以回溯到具体文档。这是后来「带引用作答」的结构前身，WebGPT 把引用收成浏览动作。
- **更新。** 换 2016 / 2018 维基索引就能改「谁是总统」的答案。后来产品里换向量库、换文档，走的是同一条物理路径。
- **仍是一次前向。** 检索 → 拼接 → 生成。没有「看完回执再决定搜不搜」的外循环。训练要微调；不是 GPT-3 那种纯上下文学习。

没有这一刀，2023 年以后几乎所有「接企业知识库的助手」会缺少一个被测过的名字和默认流水线。名字沿用了；实现常常换成「嵌入 + 提示拼接」，不再做论文里的 token 级边际化。

## 对 AI Agent 的影响

本笔记里，有外部知识的 Agent 几乎都先经过「生成之前先检索」。RAG 提供的是这条路径的**单次形态**：决策核心仍是一次生成，外部知识以检索段落的形式进入上下文。它补的是 GPT-3 窗口装不下、权重改不了的那一块，不是循环本身。

| 论文里的机制 | 后来在 Agent 里对应的物理事实 |
| --- | --- |
| 非参数索引（原文块） | 工具回执、代码库、文档可以先被检索再进窗口 |
| 索引热替换 | 不必为每份新知识微调模型；换库即换记忆 |
| 生成条件于 \(z\) | 当前观察里出现「检索到的证据」；幻觉被压低，但证据选错仍会错 |
| 一次检索 + 一次生成 | 仍是流水线。Agent 循环要的是根据回执再决定下一步（再搜、换查询、放弃） |
| 不用检索监督也能微调 | 后来许多系统连这步微调也省掉，只把检索结果拼进提示 |

因此时间线把它标成底层能力里的**工程化**：有外部知识的 Agent 几乎都先经过这一刀。它仍然不是 Agent。一次调用答完一道开域题；没有多步环境循环，也没有工具接口协议。
