**一句话主线：** 现在是 2026 年 9 月。这一页不是年表，是**观察提纲**——顺着 2024–2026 已经露出的缺口，列出值得盯的方向。厂商路线图、未交付的 JIT 凭证、未铺开的 Slack 之外表面，一律当假设，不当事实。有了一手来源（论文、官方公告、可复现仓库）再升格进里程碑表。

上一页：[2026](../../2026/overview/)。采信门槛见 [调研方法](../../overview/research/)。总弧线见 [概述](../../overview/)。

## 和 LLM 的关系（观察，不是结论）

2026 已经把矛盾推到模型之外。2027 仍可能被模型层再改写一次，但只有改写了 **Agent 能做什么的前提** 才值得记进主线，例如：

- 长程可靠性是否从「偶尔跨天」变成「默认可跨天」（失败模式、回放、可停可续）。控制流的终止条件与恢复，不是更多 token。
- 推理成本是否降到让组织敢把 ambient / routine 开满，而不是只给编码开。经济性会压过智力。
- 是否出现真正的 **Agent 专用模型**（为工具循环、电脑操作、组织身份训练），而不只是通用核 + 运行时套件。核仍不是 Agent。
- 多模态操作（屏幕、内部网页、设计稿）的可靠度，是否逼近 2025–2026 编码线已经达到的「能交 PR」。第一层通道（像素）已通，第二层谓词仍低。

这些在没有分数、没有复现、没有持续产品行为之前，只是问题，不是里程碑。

## 建议盯住的线索

按本站六类，**预先分类「如果发生，它算哪一种」**，避免到时候被通稿带着走。

### 身份与权限（接 2026 Tag / Agent Identity）

- **JIT 凭证：** 用户当场批准一次敏感动作，而不永久扩大 agent scope。来源线索：身份博文的「What's next」。有 API、有审计日志再记 **工程化**；只有 keynote 不算。
- **身份叠加：** 频道 profile ∩ 请求者本人权限。这会部分收回 2026「频道成员共享同一 bundle」的激进模型，可能是 **范式更替**，也可能只是 Enterprise 开关。主体（principal）如何叠加，是协议问题，不是文案问题。
- **非 Slack 表面：** 同一套组织身份出现在文档、工单、IDE、邮件。那是 Tag「从 Slack 起步」这句话有没有兑现。算 **工程化**，不要提前写成已经全公司打通。

### 协议与运行时（接 MCP / A2A / Skills / Code 运行时）

- MCP 是否还是工具层默认方言，还是被下一代协议换掉。换掉才是 **标准** 事件；多几个 server 不算。MCP 是接线，不是循环。
- A2A 有没有从发布会走进可互操作的生产（发现、鉴权、失败处理）。对照 [前传 FIPA](../../before2022/early-concepts/fipa-acl/)：标准可以先于生态，也可以死于无生态。
- Skills 是否成为跨运行时的专长格式，还是锁在一家模型厂商。装载格式 ≠ RPC。
- 终端运行时（Claude Code / Codex CLI 等）与团队运行时（Tag）是否共用配置、身份、评测，还是继续分叉。Framework / Runtime / Protocol 三者仍须分列。

### 基础设施（接 Aries / SpecBox / 沙箱生命周期）

- 沙箱就绪与调度，有没有从论文变成云厂商默认。那是 **工程化**。
- Agent 负载的计费与隔离，是否从「按 token」补上「按沙箱·分钟 / 按出站」。经济性维度会第一次压过智力维度。
- 自托管 runner 能否用上组织级 Access bundle（2026 文档里还不行）。

### 评测与证伪（接 SWE-bench / OSWorld）

- 出现「团队任务」基准：多驾驶员、异步、带权限边界——而不只是单仓库 issue。观察通道的第二层（完成谓词）目前没有组织尺度的尺子。
- 某一路线被公开证伪：例如纯 GUI 电脑操作长期达不到编码线，产品退回 API/MCP；或纯多 Agent 编排再次证明不如单运行时 + 好工具。这类记 **证伪/警示**，和 2023 泡沫同等重要。
- 刷榜与真实留存继续分叉。只报 SWE-bench、不报回滚率的，维持 2024 的打折读法。Verified 与 Pro 仍不可横比。

### 应用形态

- 研究型 Agent、编码 Agent、电脑操作、团队频道：四条线是收敛进一个入口，还是继续分产品。
- 个人知识工作（[Cowork](../../2026/cowork/)）、自托管频道 Agent（[OpenClaw](../../2026/openclaw/)）、组织工作区（[Tag](../../2026/claude-tag/)）是收敛、分叉，还是长期三套权限模型并存。主体不同，不能合成一种产品。
## 监管与合规：已发生，不是待观察

2026 年已经有三件事落地，**这一条不再是「若」**：

- [加州 AB 316](../../2026/california-ab-316/)（2026-01-01 生效）：被告不得以「AI 自主造成损害」抗辩。美国第一条规定自主行为后果归属的法条，不提 agent，也不要求审计。
- [欧盟 AI Act 第 50 条](../../2026/eu-ai-act-article-50/)（2026-08-02 生效）：官方指南**明文点名 AI agent 与多 Agent 架构**，要求设计上披露人工性质与所代表的人。同日加州透明度法也生效。
- [出口管制](../../2026/export-control-2026/)（2026-06-12）：已商用前沿模型的访问权第一次被当场关掉。

**下一步盯什么：**

- **审计留痕会不会成为强制项**。目前没有任何法域要求 Agent 的审计日志：「出了事谁负责」有了答案，「怎么查清出了什么事」还没有。
- **准入是否从「披露」升级到「许可」**。美国方面 2026 年只有议案（无生效法），欧盟的高风险义务被推迟到 2027-12 / 2028-08。
- **管辖口径会不会成为常态**。出口管制按「人」的国籍管，结果是厂商只能全量停用——这种口径的代价值得继续观察。
