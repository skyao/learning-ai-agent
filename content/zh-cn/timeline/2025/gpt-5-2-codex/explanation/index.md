## 当时解决了什么问题

编码 Agent 最硬的约束一直是窗口：轨迹一长、观察一多，工作集就满，只能截断或重启一轮。2024 年 [o1](../../../2024/o1/) 把「想」内化，2025 年 [GPT-5](../../gpt-5/) 把快答与思考路由进同一个系统，但**任务持续长度**这条线靠的是窗口与上下文管理，不是推理能力。

上下文压缩把这条线往前推了一格：模型跨多个上下文窗口保持连贯，意味着任务的连续时间不再由单窗口大小直接截断。system card 把这条与长时间运行的评测挂钩，方向是清楚的。

Windows 原生沙箱是另一半：Codex 的默认执行面此前在 MacOS 与 Linux 上更自然，Windows 用户要么绕 WSL，要么自己解决隔离。原生沙箱把 Windows 变成一等公民的执行环境。**这与沙箱怎么实现无关，只与 Agent 能在哪执行为准。**

## 对后续 LLM 与 Agent 的影响

同一天发布的还有 [Agent Skills 开放标准](../../agent-skills-standard/)——一边是能力包跨客户端可移植，一边是编码核跨窗口连续工作。两件事合起来说明 2025 年底的编码 Agent 竞争点已经不在单轮补全质量。

要克制的地方：这条是**点版本**，不是换世代；厂商自报的基准分数未能一手核实，不能拿来与 Verified / Pro 的历史分数连成曲线。它的可核对意义只有两条——压缩与 Windows 沙箱写在 system card 里。
