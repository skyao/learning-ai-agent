## 当时解决了什么问题

2025 年的编码运行时都在开发者的终端或编辑器里启动：Claude Code、Codex CLI、Cursor。任务却常常从对话里冒出来——一段报错贴、一串复现步骤、一句「这个谁看一下」。这一步把**触发面**搬进 Slack：不用切窗口、不用复述上下文，@ 一下就有一个会话在跑，进展回到线程里。

按定义这 **是** Agent：有目标、在仓库与 shell 上产生副作用、按执行回执继续。变化集中在两点。一是**上下文来源**：频道与线程历史自然成为任务描述，不再需要手写 prompt。二是**委派可见性**：同事看得见会话在跑、在哪个仓库上跑。

## 对后续 LLM 与 Agent 的影响

执行面没动。公告没有提新的沙箱、权限或停止语义，任务仍路由到 Claude Code on the web。所以这条不该写成「团队 Agent 就此成立」——它改的是控制面。

它的意义是提前摆好了 2026 要处理的接口：当同一个循环面对「谁在委派、谁看得见、以谁的名义」时，产品形态已经在这儿了。半年后的 [Claude Tag](../../../2026/claude-tag/) 把 beta 收成组织级产品，并第一次正面处理主体（principal）与沙箱生命周期。
