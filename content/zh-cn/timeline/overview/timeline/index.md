先明确 AI Agent 的定义，再按照时间线整理相关资料。首先要明确：[什么是 AI Agent](/definition/what-is-ai-agent/)、[什么不是 AI Agent](/definition/what-is-not-ai-agent/)。

按时间线学习 AI Agent，是为了摸清 AI Agent 发展的脉络，不能简单的罗列信息。

另外：AI Agent 不是 ChatGPT 之后才突然冒出来的产品名词。它是「语言模型支持多步决策」之后，通过工具、环境、协议、评测等方式逐步演化出来的软件形态。因此，在整理每一年的 AI Agent 材料时，都要问自己同一个问题：**这一年 LLM 多了什么能力，Agent 因此才能做什么，什么仍然做不到。**

本栏目是时间线的入口。定义、边界、里程碑类型和采信门槛见 [调研方法](./research/)。论文、产品、协议、基础设施的精读在其他栏目，时间线只负责整理发展的脉络，细节内容在其他栏目展开。

## 时间线主脉络

AI 社区信息量太大，为避免噪音必须将关注点聚焦为 **LLM Agent**：以大语言模型为决策核心，能在多步循环里执行行动、接收反馈、再次决策，直到目标完成或失败。单轮问答、一次工具调用、行级代码补全，都不算 AI Agent；更早的符号 Agent / RL Agent 只作为 [2022 年之前](../before2022/) 的前传。

所以 Agent 史不等于 LLM 史。语言模型年年在进步，写进 AI Agent 时间线年份页中只有**改写了 AI Agent**的那些变化：推理能不能多步、工具接口是否稳定、上下文够不够撑住一次长任务、能不能看见屏幕和代码库。

Agent 和 LLM 的关系，可以理解为一条 Agent 发展的主脉络：

| 阶段 | LLM 给了什么 | Agent 因此是什么 |
| --- | --- | --- |
| 前传 | 还不能当可靠规划器 | 符号 / RL Agent，只作渊源 |
| 底层能力 | 从 Transformer 到可对话与思维链 | 循环尚未产品化 |
| 接口 | 结构化工具调用、更长上下文 | 第一次能工程化的实现「想—做—看」 |
| 可验证 | 编码 / 多模态 / 长窗口 | 能打分的任务型 Agent |
| 内化 | 推理模型、原生 agentic | Runtime产品，协议开始统一 |
| 外溢 | 长程自主仍在演进，瓶颈外移 | 团队身份、沙箱、调度、审计 |

## 按年组织时间线

每年的发展总结为一句话。点开年份页看细节、里程碑和「还做不到什么」。

- [2022 年之前](../before2022/)：Agent 前传。决策核心还不是 LLM；底层能力开始出现。
- [2022](../2022/)：底层能力就绪。可对话接口和思维链出现，Agent 循环尚未产品化。
- [2023](../2023/)：Agent第一次工程化。ReAct 给出循环，Function Calling 给出接口，AutoGPT 点燃舆论。**AI Agent 之路从这一年正式开启。**
- [2024](../2024/)：评测与协议。编码 Agent 成为可验证主战场；MCP 发布时并不热闹，后来才被追认为拐点。
- [2025](../2025/)：Runtime产品。Agent 从开发类库变成可直接手机用的Runtime；协议层从 MCP 扩到 A2A。
- [2026](../2026/)：团队与基础设施。个体编码 Agent 之后，问题变成组织身份、共享工作区和执行路径。
- [2027](../2027/)：梳理清晰发展脉搏和现状之后，才有资料谈展望未来。

## 每年的调研整理思路

年份页共用同一个架构，主题要清晰，避免写成新闻和资料的流水帐：

1. **一句话总结** — 总结这一年中 AI Agent 的发展阶段，足够清晰和明确，加入到时间线中
2. **和 LLM 的关系** — 模型这一年改写了哪些前提
3. **里程碑** — 按 [六类](./research/#里程碑类型) 标注：首证 / 工程化 / 标准 / 引爆 / 证伪 / 范式更替
4. **能力栈切片** — 模型 · 框架/协议 · 应用 · 基础设施，各写几条，不求全
5. **能力约束** — 牢记还有什么内容是现阶段还没能做到的
6. **深入研究** — 细节链接到资料、产品、协议、基础设施的页面

整理材料的时候要同时注意两种信号：**当时热度**和**后来是否站得住**。例如： AutoGPT 的 star 数曾经远高于任何可靠 Agent；MCP 发布当年很多人没当回事。类似的错位本身是 AI Agent 发展过程的重要部分。
