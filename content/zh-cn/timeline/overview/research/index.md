注意：本页讲的是调研和整理 AI Agent 资料的方法，不是 AI Agent 知识本身。
## 调研对象

AI Agent 是以大语言模型为决策核心，在多步循环里对环境采取行动，并根据反馈继续迭代，直到目标完成或失败的软件系统。

这个定义里有四个必须同时具备的要素：

1. **LLM 为决策核心** — 不是规则、纯 RL、符号规划器
2. **多步循环** — 不是单轮问答、单次工具调用
3. **对环境采取行动** — 不是纯文本输出
4. **反馈驱动的迭代** — 不是无观察的批处理

下面是本次调研的 5 个决策点。

## 1. 边界 {#agent-边界清单}

| 形态 | 判定 | 理由 |
| --- | --- | --- |
| 单轮对话（ChatGPT 问答） | 否 | 无多步循环、无行动 |
| 单次工具调用（"帮我查天气"→ 调一次 API） | 否 | 无循环，是底层能力 |
| Function Calling | 否，分类为**协议** | 模型扩展方式，是底层能力，不是软件系统 |
| 多步工具编排、沙箱循环 | 是（弱自主） | 有循环有动作 |
| 自主编码 / 电脑操作 / Deep Research | 是（核心对象） | 端到端任务 |
| 行级 Copilot | 否；存在 Copilot→Agent 演化 | 无目标终止条件 |
| 符号 / BDI / 纯 RL | 否（主线） | 核心不是 LLM |
| 多 Agent 协作 | 是（作为**一种架构形态**） | 属于 LLM Agent |
| 机器人 / 自动驾驶 | 否（相邻） | 物理控制，体系不同|

切割之后，主线是软件形态、LLM 驱动的执行系统从无到有。更早的 Agent 文献只作前传，避免写成一部 AI 通史。

## 2. 能力分层 ≠ 单条分类

年份页用四层看「当年能踩在什么上」。分类回答「这条材料是什么」。

Function Calling 作为能力出现在模型层叙事（核开始能稳定选工具）；作为里程碑归**协议**。Claude Code 在能力栈是运行时，分类是**产品**。

```text
应用     编码 / GUI / 研究 / 通用任务
框架·协议  编排库 · 运行时 · 接线协议
模型     条件生成、工具选择、窗口、视觉、测试时计算
         基础设施横切：沙箱 / 评测 / 观测 / 身份
```

**模型层：** CoT → 推理模型；prompt 赌 JSON → Function Calling → MCP / Skills；窗口 4k → 1M+（轨迹工作集上限）；像素输入；长稳。

**框架 / 协议：** 编排库（LangChain → AutoGen → Agents SDK，分类=框架）；代码优先运行时（Claude Code、Codex CLI，分类=产品）；协议：Function Calling（模型↔工具）→ MCP（模型↔资源，2024-11）→ A2A（Agent↔Agent，2025-04）→ Skills（运行时装载，2025-10）。记忆：窗口 → 分页（MemGPT）→ 频道记忆。

**应用：** 编码（证据最密）、GUI/浏览器、Deep Research、通用助理。行业演示默认不进表。

**基础设施：** 沙箱是执行边界；评测单独成分类，因为「宣称」vs「谓词」反复分叉（HumanEval → SWE-bench 族 → OSWorld → Terminal-Bench）。

**层间接口：** schema 标准化落在模型↔宿主（Function Calling 记协议）；MCP / Skills 落在宿主↔工具；专用权重（coding / CUA）落在应用↔模型。史实多半发生在接口上，不在某一层内部。

## 3. 比较维度

同一套轴，避免各说各话。与里程碑标签不是同一件事。

| 维度 | 内容 | 度量 |
| --- | --- | --- |
| 自主度 | 每步确认 / 关键审批 / 放手 | 无行业 L0–L5，按任务标注 |
| 范围 | 单仓库编码 → 通用电脑 | 基准覆盖 |
| 可靠性 | 成功率、复现、失败模式 | 基准分数、回滚、留存 |
| 经济性 | token、延迟、沙箱时间 | 实测与定价 |
| 扩展 | 长任务、跨会话、并发 | 窗口、记忆、沙箱寿命 |
| 影响 | 被采用、被并入默认路径 | 不是通稿里的「革命」 |

机制观察（Reflection / Tool use / Planning / Multi-agent）用来看环内部用了什么原语，何时变成标配。

## 4. 进表规则

防流水账，也防只写赢家。每条：**分类一、标签可多，也可无**。侧栏 `[分类]条目名`。前传八条概念不套八类。

### 分类

1. **论文** — 剩余类（ReAct、InstructGPT、PaLM、Aries）
2. **模型** — 换核（GPT-3、GPT-4、Claude 3、o1、o3）
3. **产品** — 可打开的应用或运行时（ChatGPT、Claude Code、Assistants API）
4. **框架** — 编排库 / SDK
5. **协议** — Function Calling、MCP、A2A、Skills
6. **评测** — HumanEval、SWE-bench 族、OSWorld、Terminal-Bench
7. **博文** — Building effective agents、Agent identity
8. **监管** — 法规、指南、政府指令、司法先例（欧盟 AI Act 第 50 条指南、出口管制、加州 AB 316）

- 有论文不等于分类是论文。知名模型走模型；评测论文走评测；可跑系统走产品或框架。
- **分类看对象是什么，不看材料挂在哪。** 政府行为走**监管**，不因为是厂商博客发布的就归博文——材料只是载体。同理，只有厂商通稿、没有实际监管效力的事件也不因「像政策」而进监管。
- Function Calling 与 Skills 进协议，与 MCP、A2A 并列。
- 发布会不当条。2023-11 记 GPT-4 Turbo 与 Assistants API，不记 DevDay；GPTs 不升格。
- 同名不同物跟主对象：2025 云端 Codex 是产品，不是 2021 那只模型。Tag 机制文档与 Slack 切换并进 Claude Tag。

| 条目 | 分类 | 标签 |
| --- | --- | --- |
| ReAct | 论文 | 首证 |
| InstructGPT | 论文 | 工程化 |
| ChatGPT | 产品 | 引爆 |
| Function Calling | 协议 | 工程化 |
| SWE-bench | 评测 | 首证、警示 |
| MCP | 协议 | 标准 |
| Claude Code | 产品 | 工程化、范式更替 |
| GPT-4 | 模型 | （无） |

### 标签 {#里程碑类型}

1. **首证** — 第一次证明某类能力（ReAct）
2. **工程化** — 把某项此前只被演示、未被交付的能力第一次交到他人手上：有 API、有运行时、是可买产品，或有可运行的官方实现
3. **标准** — 多方默认（MCP 被追认、Verified）
4. **引爆** — 采用或舆论陡增（AutoGPT、OpenClaw）
5. **警示** — 谓词揭穿宣传（SWE-bench 个位数、Pro ~23%）
6. **范式更替** — 改写前提（测试时计算、组织身份）

「工程化」只标转折点，不标稳态。模型换代、既有形态的新实例或更新、没有交付物的论文与博文，都不带这个标签。

标签记的是历史角色，而角色是少数。2025 年之后 Agent 本身就是产品形态，「做成产品」不再是角色，而是入场条件，因此后期许多产品与模型条目标签为空；在那些年份真正有区分度的是标准、引爆、警示与范式更替，它们描述的是偏离常态。

标签不改变分类：Claude Computer Use 是产品，不会因为带「工程化」而被归到协议。

### 采信

- 一手来源：论文、官方公告、可复现仓库
- 当时热度 ≠ 后世重要性（MCP）
- 当时已有的反方意见并列，不事后发明批评

## 5. 反查

1. 幸存者偏差：LangChain 主导过 2023 也被广泛批评；死掉的 AutoGPT 克隆定义了当年舆论。
2. 厂商通稿 vs 第三方谓词。
3. star / 演示 ≠ 完成率。
4. 禁止把后来才清楚的重要性写成当时已注定。

## 术语

- **分类 / 标签**：形态 vs 历史角色
- **Agentic**：属性，不是产品类型
- **ReAct 环**：Thought → Action → Observation → 再选
- **Tool calling / Function calling**：前者泛指；后者特指 2023-06 OpenAI API。分类=协议
- **Framework / Runtime / Protocol**：库 / 装上即委派的执行环境 / 接线。2025 年三者终于能用产品对上号
- **Sandbox**：副作用的地址空间
- **Eval**：完成谓词，独立成分类
- **Memory**：工作集（窗口）vs 跨会话持久化
- **Copilot → Agent**：自主度轴。行级补全按定义仍否
