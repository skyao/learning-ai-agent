Agent 这个词使用非常广泛，如果不先定义好什么是 AI Agent，后面的内容没法展开。

本页只回答：**在这份笔记里，什么算 AI Agent。** 对照清单在 [什么不是 AI Agent](../what-is-not-ai-agent/)。

## 一句话定义

**AI Agent 是以大语言模型为决策核，在多步循环里对环境采取行动，并根据反馈继续迭代，直到目标完成或失败的软件系统。**

将这个定义拆开， AI Agent 必须同时具备以下四个要素：

1. **LLM 当决策核** — 下一步做什么，由语言模型选，不是写死的规则、也不是纯强化学习策略。
2. **多步循环** — 不是问一句答一句，也不是只调一次工具。
3. **对环境行动** — 调工具、读写文件、跑代码、点界面、发请求；不只生成一段话。
4. **反馈后再决策** — 看见工具回执、测试失败、网页变化，然后重新决策。

缺任何一条，在这份笔记里就降级：它可能是很有用的模型能力、助手或 AI Agent 的前身，但不是这份笔记中要学的那个 AI Agent 对象。反例请见 [什么不是 AI Agent](../what-is-not-ai-agent/)。

## 最小循环

```text
目标
  → 想（模型决定下一步）
  → 做（调用工具 / 改环境）
  → 看（观察结果）
  → 再想 …
直到完成、失败、或人工介入
```

这个循环后来常被叫作 ReAct 循环。

## 为什么用这个定义

Agent 这个词使用实在是过于广泛，某些情况下也过于滥用。

所以本笔记坚持使用 **LLM Agent** 这个工作定义来限制 AI Agent：承认更老的 Agent 传统只是[前传](/timeline/before2022/)，AI Agent 的发展主线从语言模型能多步决策之后才开始。

两个容易混的词：

- **Agent**：满足上面 AI Agent 定义的软件系统。
- **Agentic**：形容词，表示「有自主行动倾向」。一个模型可以很 agentic，但一次聊天仍不是一个 AI Agent 产品。

## 四个都满足才算 AI Agent

**把「修这个缺陷并开 PR」交给编码运行时。** 模型读仓库、改文件、跑测试、看失败、再改、推分支。LLM、多步、行动、反馈四条都在。自主程度可以不同（每步都问你，或只在提交时问），但形态已经是 AI Agent。

按照这个标准，这些也算 AI Agent：

| 形态 | 为什么算 |
| --- | --- |
| 多步工具编排、沙箱里写代码再根据测试改 | 有循环、有行动、弱自主也算 |
| 自主编码 / 电脑操作 / Deep Research | 端到端任务，本笔记的核心对象 |
| 多个 LLM 角色协作 | 仍是 LLM Agent，只是一种架构 |

「弱自主」也算：人可以随时转向、审批。Agent 不是「完全没人管」的同义词。自主度是高级维度，入门只要求循环存在。
