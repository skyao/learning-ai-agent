## 官方说了什么

Singleton 给出了 Muse 赏金计划的第一组总量：约 120 万美元已支付（首帖表述为超过 100 万美元，后续帖细化为约 120 万美元），收到 630 份以上报告，其中 64 项有效。计划 4 月起私下运行，2026-09-08 产品发布后转为公开，目前仍在开放中。单项赏金上限为 300,000 美元，其中针对单用户的 prompt injection 上限为 130,000 美元。

领衔案例是一起上线前约 4 个月、在早期内部测试期发现的认证缺陷：认证检查信任本地代理附加的一个请求头，把它当作“请求安全”的证明；一次迁移中加入第二层代理后，来自外部的请求也可以携带该请求头。暴露范围是内部测试人员的 token 与对话，限于上线前的虚拟机。Singleton 称处置是关停整个服务、移除该请求头、不再信任本地机器，并把教训归纳为持续检验假设、移除基于请求头的内部信任。

线程还提到另外两类发现：恶意 Android 应用可经未验证链接拉取凭证，以及 Mac 应用的自动更新器可被已获得本机访问权限的攻击者利用以提升权限。这两项的修复状态、是否影响生产用户、发现时间与赏金金额，在我所见的线程摘要中均未说明，我只记线索，不作事件结论。

## 我的理解：三处需要分清的边界

第一，$300,000 与 $130,000 是上限，不是实付。我此前整理的赏金线索里，这两个数字并存而未分清实付与上限；这轮线程把两者统一为上限口径——300,000 美元是单项报告上限，130,000 美元是其中单用户 prompt injection 一项的上限。RuntimeWire 标题把上线前认证缺陷标为“$300K 缺陷”，但单凭我所见的线程摘要，不能断定该缺陷的实付金额恰好等于上限值，这一项我记为未核实。把上限读成实付，是这类赏金新闻最容易滑过去的地方。

第二，这起认证头缺陷与我此前整理的 KVM 逃逸抢修不是同一事件。两者都是上线前发现，但机制不同：前者是认证检查信任了本机代理附加的请求头，后者是虚拟机逃逸出宿主隔离。同样，线程提到的 Mac 自动更新器线索，也不能与 Wardle 9-21 披露的 Mac App 零日（dictation endpoint 配置项）合并——机制描述不同，合并会虚构出一个并不存在的“同一缺陷被反复发现”的叙事。

第三，这不是一起新增的生产安全事件。认证缺陷的暴露范围明确限于内部测试人员与上线前虚拟机，Singleton 也称若进入上线后用户环境后果可能严重——这个条件句恰恰说明它没有进入生产环境。我不把它计入生产安全事件，也不因此改动此前五起基线事件的结论。它的学习价值在另一处：对 agent 这种“替用户持有凭证、替用户行动”的系统，内部信任假设（本机附加的头就是安全的）一旦被一层新增的代理打破，认证边界就会静默失效；而发现它靠的不是上线后的用户报告，是上线前内部测试加赏金计划的组合。
