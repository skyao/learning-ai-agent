## 评测梳理了什么

这是第一篇系统梳理 Muse「管钱」能力的评测。功能清单包括：连接账户后追踪支出与预算、审计订阅并标记异常扣费、发现重复扣费、代为谈判账单（包括致电服务商）、检索无主财产数据库并协助申领、找优惠与比价。背景是 Connect 上首席 AI 官 Alexandr Wang 发起的 #MuseMoneyChallenge，让 Agent 找出 1,000 美元节省额。

Meta 在评测中的口径：付款与花钱前须用户批准；没有存卡时使用一次性卡号；密码与支付信息对 Agent 本身也不可见；保留完整操作记录。同时 Meta 也承认 Muse「并非不受攻击」「有时会犯错」。

第三方态度：身份盗窃资源中心（Identity Theft Resource Center）表示这项技术「太新」，目前不推荐用户把理财交给它。

## 我的理解：理财是信任门槛最高的场景

购物场景里 Agent 犯错，代价通常是一笔可退的订单；理财场景里它接触的是账户全貌、订阅扣费和谈判授权，错误与越权的代价更高，恢复也更难。这篇评测的价值在于把「能力清单」和「信任门槛」放在同一页：功能越全，越需要逐项核对批准粒度、操作记录和撤销路径。

它与 [财报数据](../../product/earnings-and-scale/)互补：官方说购物是最常见用途、单笔金额不低；评测则说明独立机构对把钱交给 Agent 仍持保留态度。两者不矛盾，前者是使用规模，后者是信任成色。

## 后续要核对的

- 谈判账单时的授权范围：一次授权覆盖单次通话，还是持续有效？
- 无主财产申领涉及身份材料提交，凭证与证件在流程中如何流转？
- 异常扣费标记的依据与误报处理，是否有可复核的记录格式？
