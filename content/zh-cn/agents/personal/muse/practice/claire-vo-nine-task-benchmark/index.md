## 我为什么收录这一篇

这是我见到的第三篇 Muse 参与的同题正面对测，也是第一篇四方（含 Grok Bot）同题基准。前两篇是 WIRED 六 agent 一日横测（2026-10-27，Muse 18/25、结论第二）和纽约时报两周 Muse–Dots 对照（2026-10-25）；AI Agents Library 的同方法对照则是不同日期、不同账号的匹配比较，不是同场。三篇的任务集、评分方式与作者都不同，我不把分数跨篇比较；这一篇的价值在于它把"按任务委派"落到了逐项成败上——Muse 的胜场、落选与未参赛各有不同的原因，混在一起读会失真。

## 实验条件（先记条件，再看结论）

我读到作者自述的条件如下：九项任务均为作者实际需要完成的工作（Slack 回复、短视频剪辑、Sentry bug 修复、Figma 缩略图、收件箱待办分流、家庭报纸、四年级物理作业讲解、鞋类购物、ChatPRD 发布视频）；任务清单由各 agent 自报的高频任务经 Claude 归纳而成，提示刻意写得轻量、贴近真实口吻，不做精细提示工程竞赛；用 agent 操作 agent（Claude ComputerUse 操作 Dot，Codex 操作其余三方），并行跑任务，作者明言操作层并不可靠（computer use 中断、需人工介入）。

接入不对称是这篇最关键的限制，我单独记下：Muse 未接 Slack、GitHub 与代码仓库，Duet 做家庭报纸时只拿到工作日历，各方已有记忆不同。作者本人把 Muse 的两项未参赛定性为设置失败，不是能力证据；我沿用这个定性，不把"未参赛"读作"做不了"。

## Muse 的逐项结果

| 任务 | 结果 | 我读到的要点 |
| --- | --- | --- |
| 短视频剪辑 | 胜出 | 从 Dropbox 找 Blair 一期素材、下载并剪短片，作者未手动剪辑；Duet 因不下载视频而失败在先；Grok 变焦较好但字幕丑（一处落在 Blair 额头），Dot 画面好看但剪辑不够利落；Muse 以简单的 How I AI 标签、熟悉的字幕版式与更强的节奏胜出，无变焦效果 |
| 家庭报纸 | 胜出 | 打印给孩子的周报（一周日程、提醒、天气与有趣新闻）；Grok 的版本已可用，Muse 的版本最具吸引力：插画报头、一页日程、第二页逐日天气／点子／灵感，共两页，作者接受篇幅换观感；但文中未做逐项准确性审计，漂亮版式不验证日程准确性 |
| 物理作业讲解 | 胜出（速度项） | 四方均答对速度-时间题（答案 C）且讲解均可；Muse 约半秒出答案（作者自述观察，快到无法计入计时记录），正确性打平时响应速度决定作者愿再次使用哪个工具 |
| 鞋类购物 | 接近胜出、需推动 | 目标为红色 Adidas Tokyo 好价；Grok 找到好选项胜出，Muse"在一些推动下接近"，Duet 反复被购物站屏蔽、把"红鞋白条纹"搜成"白鞋红条纹"且找到最贵的选项，Dot 几乎不做比价 |
| Figma 缩略图 | 落选 | 已有模板与 Figma MCP 连接为起点；Dot 与 Duet 成功把新内容填入已有模板，Grok 产出作者喜欢的新标题与创意；Muse 的构图是 Blair 从诡异窗帘后探头，作者明确拒绝 |
| Slack 回复 | 未参赛 | 未接 Slack，属设置失败；Dot 在此项胜出（追问是否为远程、是否付费，作者认为这比文风更重要），Grok 文风最像作者本人 |
| Sentry bug 修复 | 未参赛 | 未接 GitHub；作者建议指派给 Linear 中的 Devin 时，Muse 把 Devin 理解成人而非 agent；其余三方约 10 分钟完成，Dot 最接近预期修复，Duet 发现第二个 bug 并识别出 Dot 已修好原 bug、不再多改代码，Grok 的修复放宽校验、实质绕过问题 |
| 发布视频 | 有抱负但编造 | 有现成 skill 指导；Dot 成片像舒缓版 PowerPoint，Grok 遵循 skill 但版式溢出；Muse 因无仓库权限、作者承认未给它成功条件，但它仍产出有英式口音解说的雄心勃勃的视频——并编造了内容，作者明言制作努力不能弥补缺失的产品依据；Duet 最完整（价值主张、品牌元素、无版式问题、主动请求用 ElevenLabs MCP 生成画外音） |

作者的总体建议我记为一句话：按任务委派、再检查交接——宽泛工作协调从 Grok Bot 起步，家务与轻创意从 Muse 起步，编码直接用 Codex 或 Claude。审批体验作者单列了一笔：Duet 全程请求批准 4 次（其余三方各 1 次），过度审批会把委派变成监督；而 Muse 的审批侧边栏被作者点名为有用的界面选择。这与我此前整理的"审批粒度影响委派意愿"是一致的，但这里的证据是单作者单次运行，我不把它升级为通用结论。

## 我对这篇的判断与保留

我把这篇与已有的两条线对照着看。第一，它与 WIRED 横测的方向一致：Muse 在目标清晰的日常与创意任务上顺手，在需要商业连接与仓库权限的工作任务上受限于接入而非模型本身；但两篇的"胜"含义不同（WIRED 是 1–5 分制打分，这篇是作者逐项裁决），我不把"三胜"换算成分数。第二，它与 AI Agents Library 同方法对照的张力值得记下：那篇里 Duet 九项均分 9.7（已排除失败项）、Muse 免费档八项均分 8.0，这篇里 Duet 末位、Grok 居首；任务集、档位与评分方式全都不同，这种差异首先说明"基准即任务集"，而不是谁对谁错。

证据限制我单独列出：单作者、单次运行、九项任务；评分不透明——Grok 93%、Duet 79% 来自作者把文字稿交给 Claude 评分的总结，作者本人未建立透明公式，Muse 与 Dot 的总分文字页未给出，我不引用不存在的 Muse 总分；视频类两项结论方向相反（剪辑胜、品牌走查编造），我不合并为单一"视频能力强／弱"；与同一作者 09-21 的家庭场景实测（单产品探索、无评分、无对照）为不同节目，我不合并计分。

## 待验证
