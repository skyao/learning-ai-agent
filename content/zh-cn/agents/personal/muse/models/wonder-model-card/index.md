## 文档要点

模型卡的 MemoryBench 测试长对话中的关键信息回忆，加入干扰以及冲突或更新信息；FocusBench 关注多次交互和动态环境中遇阻后的持续推进。两者均为内部评估。比较结果还涉及推理强度、Harness 和评分方法等设置，部分结果并非在相同 Harness 下产生。

## 我的阅读重点

我重点看第 4—6 页的能力评估方法和文末的限制说明，先确认任务如何判定成功，再理解分数。页码按 PDF 阅读器的页序记录。

这份模型卡提醒我，模型名称并不足以描述一个 Agent 实验。Harness、推理强度、上下文供给和评分方法都会影响结果。部分结果的 Harness 条件不同，因此我暂不据此整理跨模型排名。

## 从模型评估到自己的任务记录

我想借鉴的是加入干扰、更新事实和设置阻碍的思路，再用可检查的任务结果定义成功。

| 关注点 | 我准备记录的证据 |
| --- | --- |
| 回忆与更新 | 新会话取回的事实、更新后是否继续使用旧信息 |
| 遇阻后的进展 | 工具错误、替代路径、需要补充的权限或信息 |
| 完成与验收 | 文件或外部状态是否满足原始目标及最新约束 |
| 实验条件 | 模型版本、Harness、账号权限、运行环境与推理设置 |

这些实验尚未复现。对我正在做的运行平台而言，这类记录还可以帮助定位问题：同样的模型结果不同，究竟来自上下文供给、工具行为还是恢复机制，需要沿执行链查证。
