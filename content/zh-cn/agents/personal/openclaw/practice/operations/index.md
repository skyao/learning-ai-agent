## 我怎样计算自建成本

| 成本 | 我准备记录的内容 |
| --- | --- |
| 宿主 | 在线时长、资源、磁盘和网络 |
| 模型 | 实际请求、回退、上下文与重试 |
| 集成 | 渠道连接、凭证更新与网站变化 |
| 状态 | 工作区、数据库、插件数据和备份 |
| 维护 | 升级、排障、恢复和人工检查 |

可自建增加可观察与可调整范围，也把部分服务运营工作交给自己。订阅费与 API 费只是总成本的一部分。

## 恢复必须回到业务验证

恢复后进程能启动，不说明计划、登录态、记忆和产物关系都正确。旧任务可能被重放，也可能失去下一次触发时间。

我准备先在独立实验目录备份，再到另一位置恢复，检查原任务、文件标记、计划和授权。数据库与配置需要来自同一可解释的状态世代；插件状态也要纳入。

对自己开发的平台，我会把可恢复性作为功能验收的一部分。尤其是长期个人代理，积累的上下文越多，一次错误升级的损失就越难从一条聊天里重建。
