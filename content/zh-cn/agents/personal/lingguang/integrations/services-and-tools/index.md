## 我读到的连接范围

[官方公告](https://www.antgroup.com/en/news-media/press-releases/1793066400000)列出支付宝账单、会员、出行，以及钉钉、飞书、邮箱、米家，并提到 MCP、CLI 扩展。它说明可连接的服务方向，没有逐项公开读写权限矩阵、商户覆盖率与每个客户端的开放状态。

我暂时不把这些名称扩写成“可以代办该应用中的全部事务”。权限属于具体连接和动作，不属于应用图标。

## 我会怎样记录一次连接

| 需要保留的项目 | 为什么单独记录 |
| --- | --- |
| 连接方式 | 原生 API、MCP、CLI 与浏览器操作有不同的失败条件 |
| 代表的主体 | 本人账号、企业空间或设备家庭成员身份可能不同 |
| 实际授权 | 能读哪些数据、能改什么、授权何时失效 |
| 动作与结果 | 调用成功、业务接受和最终生效需要不同证据 |
| 取消与撤权 | 停止新访问后，已有任务、缓存及下游动作怎样处理 |

这是我准备使用的观察清单，不是已发现的灵光内部实现。

## 支付生态不等于产品已经具有任意付款能力

读到支付宝生态时，我会先问数据、身份与交易三件事。查到账单，只能证明获得了相应信息；APASS 提供身份与信任机制，也不能替代某次购买的具体批准和支付结果。

因此，订阅分析、订阅取消、发起付款、完成退款继续分开记录。APASS 的平台说明见[安全与权限笔记](../../security/apass-and-authorization/)；本轮尚未核实灵光的完整支付操作路径。
