## 本轮没有确认的配置

我在[2.0 官方发布](https://www.antgroup.com/en/news-media/press-releases/1793066400000)中没有取得可固定的底层模型版本、模型路由、上下文上限、云实例规格或任务单位成本。蚂蚁有自己的模型与研究体系，并不足以证明每个灵光功能都使用同一款模型。

因此，这些字段暂记为未确认。媒体提到的某个版本或资源配置，后续需要与具体账号、客户端及观察日期绑定。

## 我更想评估完整委托

对持续事务，我会按下面的方法设计验证。这是评估方案，目前没有测量结果：

| 指标 | 我准备怎样记录 |
| --- | --- |
| 信息准确性 | 对照允许读取的原始数据，检查金额、日期、对象和来源 |
| 连续性 | 中断对话、补充新条件、跨日返回后，目标是否保持一致 |
| 变化识别 | 同时记录发现变化、漏掉变化和没有变化却通知的次数 |
| 及时性 | 从数据发生变化到系统成功读取，再到提醒送达分别计时 |
| 人工介入 | 统计授权、补充信息、纠错与接管，不能只计最后一次确认 |
| 业务结果 | 区分草稿、提交、第三方接受与实际生效 |
| 成本 | 同时记录前台交互和后台检查；未知收费先留空 |

我会先固定数据集与验收条件，再比较不同产品。一个账号的免费配额或者一次漂亮演示，都不适合直接换算成长期使用成本与可靠性。
