## 我读到的具体机制

当前内建记忆使用 `memories/MEMORY.md` 和 `USER.md`，默认字符预算分别为 2200、1375。会话开始时读成固定提示快照；会话中写入会落盘，但不改写已开始会话的那份提示，工具返回可显示实时状态。

超过预算会返回错误，由 Agent 整理后重试，并非默默自动压缩。这让我把“说已经记住”“工具写入成功”和“后续运行实际使用”分成三个检查点。

我的理解是，这种设计在缓存稳定性与记忆更新之间作了明确取舍。网关重启也不必然结束原会话，因此不能仅用重启验证新快照。后续会在写入后分别测试同会话、新会话及另一个已打开会话，记录信息生效范围。

外部 Memory Provider 是另一条附加路径，不应与这份有限内建记忆混成同一机制。
