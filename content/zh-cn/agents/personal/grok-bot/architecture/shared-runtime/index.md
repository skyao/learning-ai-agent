## 文档明确的边界

个人账号下的 Bot 共用文件、浏览器会话和命令行凭证；每个 Bot 有自己的操作屏幕，屏幕不构成安全隔离。[电脑说明](https://docs.x.ai/grok-bot/computer-and-apps) 官方 FAQ 将跨用户隔离说明为每用户一台 Firecracker microVM。[安全 FAQ](https://docs.x.ai/grok-bot/security-faq)

我因此把角色隔离、并发工作面和租户隔离分开看待。另一个具名 Bot 能否读取同账号文件，不能只凭它有独立头像和聊天判断。

## 我的职责视图

| 对象 | 对我有意义的边界 |
| --- | --- |
| 用户账号 | 云端电脑及已授予资源的归属 |
| Bot | 长期职责与工作上下文 |
| 操作屏幕 | 并发交互的工作面 |
| 共享文件和登录态 | 协作便利，同时扩大同账号可用范围 |
| 外部业务对象 | 最终修改落到哪个系统、谁承担结果 |

这张表是我的分析，不是厂商内部服务拓扑。

## 共享环境怎样影响可靠性

两个 Bot 分别修改同一个研究清单，即使屏幕独立，也可能覆盖文件或重复创建文档。我会验证并发时是否有可见冲突、版本核对和业务回执。

共享登录态使交接更方便，也意味着把研究 Bot 与其他职责放在同一账号，需要考虑它们实际可以触达什么。对自己的平台，我会在安排职责时明确资源范围，不能依赖角色描述代替执行权限。

多人使用的 Team Bot 又有不同的电脑选择规则，见 [团队代理笔记](../team-bots/)。
