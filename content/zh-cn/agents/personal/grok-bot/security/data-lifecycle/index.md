原始资料：[Manage Grok Bot computers](https://docs.x.ai/grok-bot/computers)、[Bot 管理](https://docs.x.ai/grok-bot/bots)。阅读：**2026-10-21**。

官方管理文档区分重建、终止和删除数据：前两者保留持久盘，终止会停止运行，之后新消息可启动新电脑；删除电脑与数据、删除全部 Bot 数据是范围更大的操作，而且属于相应企业管理入口。[电脑管理](https://docs.x.ai/grok-bot/computers)

删除单个 Bot 的配置、会话和计划，不说明共享电脑上的文件与登录态同时消失。[Bot 管理](https://docs.x.ai/grok-bot/bots)

## 我整理的生命周期关系

| 长期对象 | 需要分别检查的操作 |
| --- | --- |
| 角色和聊天 | 隐藏、复制、删除 |
| 自动化 | 暂停、取消、已开始运行 |
| 云端实例 | 睡眠、恢复、重建、终止 |
| 持久状态 | 同步、快照、删除及恢复 |
| 外部业务结果 | 文件更新、消息发送、权限改变 |

对我做运行平台，这张关系表比“重启可以解决问题”更有用。终止进程可以结束当前动作，却未必撤回授权；保留磁盘可以恢复工作，也会保留用户原本以为已经清理的会话。

## 数据控制与可观测性

[安全文档](https://docs.x.ai/grok-bot/security)还区分控制面审计、动作记录与内容导出，存在不同企业条件。我只把它作为查找具体记录的入口，不将一个审计开关推定为全部工具结果都可见。

后续实验记录实例变化前后的文件标记、登录状态、Bot 记忆和外部产物。涉及保留期、备份和组织合同的问题则保留到对应官方条款核对，不由界面删除推导全量副本已清除。
