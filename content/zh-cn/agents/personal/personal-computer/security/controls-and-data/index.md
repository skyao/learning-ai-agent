这些资料提供了不同对象的控制入口：计划的暂停和删除、活动任务的额度暂停与恢复、记忆条目的编辑删除，以及 Brain 的新增写入开关。具体产品事实分别在 [计划](../../architecture/automations/)和 [Brain](../../architecture/brain/)笔记中整理。

## 我不把所有控制合并成“停止”

| 对象 | 我需要核验的效果 |
| --- | --- |
| 一次执行 | 是否还有正在发出的工具请求 |
| 后续计划 | 下一轮是否仍会启动 |
| Brain 新知识 | 后台是否继续从活动中写入 |
| 既有记忆 | 是否仍会被后续任务读取 |
| 本地授权 | 客户端还能读取哪些资源 |
| 外部产物 | 已改文件和已发消息怎样管理 |

这张表是我的测试模型，不能据此承诺产品提供一键撤销全部影响。

## 恢复也涉及授权时效

一项任务可能因额度暂停，之后自动继续。在等待期间，资料、接收方或委托范围可能已经变化。对自己的运行平台，我希望恢复前核对这些条件，而不是只看计算额度是否足够。

同样，暂停周期不说明本轮已运行的工作结束，删除记忆也不说明其内容已从既有文件里消失。

## 数据验证需要可定位的样本

我准备在测试目录、记忆条目和外部测试对象中分别放置标记，逐项操作后检查实际变化。文档没有明确覆盖的备份、审计和第三方副本保留范围，不自行补成已删除结论。

本轮没有停止或删除真实用户数据，实验结果后续另行记录。
