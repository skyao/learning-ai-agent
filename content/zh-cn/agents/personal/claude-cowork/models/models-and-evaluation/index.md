## 模型版本需要记录，但不能代替系统评估

2026 年 9—10 月官方发布记录持续更新模型系列。我的笔记保留发布日期，实际使用时还要记录账号可选项、任务所用模型、审批方式和工具。模型名称相同，不代表执行环境、上下文与授权条件相同。

Cowork 的价值需要放在完整工作链路里评估。我关心它能否找到正确资料、在约束内处理文件、交付可继续编辑的结果，以及发现输入矛盾时是否会停下来确认。

## 我准备使用的评估维度

| 维度 | 可检查的证据 |
| --- | --- |
| 事实与引用 | 引用是否真正支持结论，日期是否对应当前版本 |
| 文档与表格 | 文件能否打开，公式和数字是否可复核 |
| 执行可靠性 | 中断后的状态、重复操作和失败说明 |
| 上下文维护 | 新约束是否覆盖旧约束，是否混入其他项目 |
| 用户控制 | 审批次数、撤销后的后续动作和权限范围 |
| 总成本 | 完成时间、人工修订、计划用量及设备依赖 |

## 用量不能只按对话条数理解

当前说明将任务消耗计入计划额度；多步检索、代码与文件处理通常比快速问答消耗更多。发布记录中赠送的 API credits 与应用内使用限制不是同一项，我不会把前者当成 Cowork 可用额度。

我也不把支持长任务写成“上下文无限”或“运行时间没有限制”。真正值得测的是：资料增长后系统怎样压缩上下文，结果是否还能追溯来源，长任务在额度或资源不足时怎样收尾。本轮没有跑基准，没有测量成功率或订阅成本，后续会用相同任务保存交付物与消耗记录。
