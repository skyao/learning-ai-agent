## 我将上下文分层记录

Projects 将相关任务、指令、文件、记忆和计划组织在一起。对我来说，它接近持续工作的组织单位，但文件、记忆与权限并非同一种对象。

| 层次 | 我关注的问题 |
| --- | --- |
| 当前会话 | 本次目标、工具结果和待审批动作是否仍有效 |
| 项目指令与材料 | 哪些规则适用于整个项目，哪些文件只是输入 |
| 项目记忆 | 结论来自什么任务，是否已被新证据纠正 |
| 账号记忆与聊天搜索 | 跨项目偏好与历史记录怎样进入当前任务 |

当前文档中，云端 Cowork 可使用聊天记忆，旧版本地任务并不共享这套聊天记忆。聊天搜索与保存记忆也分别存在：找得到旧对话，不意味着其中每条内容都已经成为长期记忆。

## 项目边界需要显式设置

Projects 默认还能使用账号记忆；如要完整分开，需要关闭项目的 Use account memory。我的理解是，项目目录更接近工作范围，不能仅凭不同项目名称就认定上下文完全隔离。

这也与我开发 Agent 时遇到的问题一致：个人偏好可以跨项目复用，但客户资料、临时推断和项目事实未必适合跨域传播。我会为这些信息保留来源和适用范围，而不是统一放进一个“用户画像”。

## 我准备验证的纠错流程

先让两个测试项目采用不同的技术约束，再更新其中一个约束，检查当前对话、项目记忆和账号记忆是否产生相互影响。纠错后继续追问旧结论，观察系统使用了什么来源。

关闭某次对话的 Memory 要在首条消息前决定，并不自动使对话不可搜索。因此我的验证会分别检查“是否用于记忆”“是否能检索到”“是否已删除”，不会把一个开关当成全部生命周期控制。
