## 我的状态清单

| 状态对象 | 我需要问的问题 |
| --- | --- |
| 对话与执行环境 | 关闭页面后是否继续，恢复时读到什么状态 |
| 本地原件与云端读取内容 | 删除哪一份，是否存在处理副本 |
| 项目与记忆 | 归档是否仅影响入口，旧结论是否仍可被使用 |
| 计划定义与每次运行 | 删除源对话是否会停止后续触发 |
| 授权和凭证 | 停用工具与删除历史是不是独立操作 |

我把这些对象分开，是因为用户经常以“结束这件事”表达意图，而系统可能只关闭一个会话入口。

## Enterprise 统一体验提供的具体例子

当前 Enterprise 统一体验 Beta 文档描述，沙箱空闲时可以停止并保存加密磁盘快照，环境从创建起有 30 天生命周期。这个范围只适用于该文档描述的体验，不能推成所有 Cowork 会话都保留相同天数。

文档还明确区分保留策略范围：计划及其运行不会因源对话删除而自动结束，记忆等派生对象也有独立的处理条件。我的结论是，需要按资源核对删除与保留语义，不能用一个“会话删除”概括整个工作链路。

## 本地与云端也分别验证

项目归档不等于删除设备上的原文件；停用记忆也不等于清除已保存记忆。我的实验会准备可追踪的测试事实和测试文件，再分别执行停用、删除与重新打开，检查结果。

我希望运行平台能把这套关系显式展示：一个计划产生了哪些运行，读取了哪些资源，形成哪些记忆和产物。这样用户取消长期委托时，系统才能给出具体结果，并说明还有哪些独立资源需要处理。

本轮仅记录公开产品文档，不推定内部备份与删除实现，也不把组织版 Beta 的规则泛化到个人套餐。
