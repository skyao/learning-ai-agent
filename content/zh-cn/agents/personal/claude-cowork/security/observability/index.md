## 我关注的官方能力

当前 OTel 帮助面向 Team / Enterprise，覆盖云端与本地会话，并分别要求支持的 Desktop 版本。事件可以记录工具调用、审批决定、文件访问与模型请求等，通过 `prompt.id` 关联同次输入触发的活动。

对我做运行平台的工作，这比只保留最终回答更有参考价值。一次任务失败，可能是模型没有理解约束、连接器授权失效、本地文件离线，或者用户拒绝了某个动作；最终结果相似，但修复方式不同。

## 内容采集还有入口差异

当前版本默认主要输出元数据，内容采集由 `otlpContentCapture` 等设备策略控制。帮助也提醒旧版本默认行为可能不同，且设备策略并不覆盖所有入口：云端计划、Web / Mobile 发起的会话，以及统一体验中转入云端的聊天有各自范围限制。

所以“开启了日志”还不是完整说明。我需要同时记录客户端版本、会话来源、采集策略以及实际事件字段。本轮没有连接采集器，尚未验证事件完整性。

## 我希望平台具备的可追溯关系

| 关联 | 我想回答的问题 |
| --- | --- |
| 用户输入 → 任务与子执行 | 为什么发起这个动作 |
| 工具调用 → 授权与审批 | 当时依据什么权限 |
| 文件与来源 → 交付物 | 结论和产物从哪里来 |
| 计划 → 多次运行 | 重复、跳过和恢复发生在哪次 |
| 模型请求 → 用量 | 哪个阶段消耗主要资源 |

这些是我自己的平台需求整理。厂商列出了事件类型，不意味着其中已经包含所有业务结果。后续我会检查日志是否足以复盘一次任务，同时控制日志本身携带的敏感内容。
