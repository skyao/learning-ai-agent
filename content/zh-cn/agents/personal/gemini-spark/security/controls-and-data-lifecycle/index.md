## 同样是 Stop，作用范围不同

Chrome 帮助区分了两个入口：在侧栏停止浏览可能促使 Gemini 换远程浏览器、换工具或放弃；在 Gemini 输入框中停止，才是完整取消任务。[官方停止说明](https://support.google.com/chrome/answer/16821166?hl=en)

我觉得这个区别很值得记下来。对运行平台而言，停止一个执行器和撤销整个目标是不同事件；用户界面如果都使用相似的按钮，就需要把实际范围讲清楚。

假设我看到浏览器准备写错文件而点击停止，我想表达的可能是“整项委托到此结束”。平台若理解为“换一条工具路径继续”，就会产生预期偏差。后续实验要同时观察按钮反馈和实际工具请求，不能只检查当前页面是否停止变化。

## 删除关系比聊天列表更复杂

| 管理动作 | 官方文档描述的范围 |
| --- | --- |
| 删除任务线程 | 同时删除任务、相关 Activity 和关联计划；不删除已创建或修改的文件，也不删除远程浏览器 / 代码数据。[任务管理](https://support.google.com/gemini/answer/17094196?hl=en) |
| 清理远程数据 | 浏览器数据与代码执行数据有独立清理入口。[Task 总览](https://support.google.com/gemini/answer/17094507?hl=en) |
| 关闭 Task 模式 | 删除远程浏览器和代码数据，本地 Chrome 数据保留；任务、线程、计划及相关文件不删除，工作暂停。[Task 总览](https://support.google.com/gemini/answer/17094507?hl=en) |

这里我只记录文档明确给出的范围，不能据此承诺所有备份、审计和第三方服务副本都已同步删除。

## 我的数据关系视图

我把任务线程、触发计划、运行数据、应用内产物与外部动作分别看待。线程是用户找到工作的入口；文件和日历是业务系统里的对象；远程环境还可能保存临时材料和会话。

对自己的平台，我希望管理界面能解释一个操作会影响哪些对象，并提供结果回执。例如，删除任务历史后，一份已经共享的文档仍然存在，就需要明确其管理入口。任务记录的消失本身不能作为业务效果已经撤回的证据。
