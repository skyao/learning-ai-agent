## 我目前如何定位它

读完这一轮资料，我保留此前的分类：DeepSeek Harness 可以纳入 Personal Agent，具体属于可配置的个人工作代理。它既有桌面 / Web 使用形态，也提供可组合运行时；是否具备完整的长期个人服务能力，还要看实际配置与验证。

与第一批的 Cowork、Personal Computer 比较，它能让我研究个人任务怎样落到工作区和产物；与 OpenClaw、Hermes 比较，它又提供了另一种插件组合和状态建模样本。这个双重视角是我将它纳入清单的主要原因。

## 我最想带回平台开发的三个问题

首先是**状态的归属**。Session 事件负责一段执行过程，长期记忆需要另行配置，Host 作业保存触发计划，Goal 记录目标阶段与继续执行资格。把这些对象分开后，才能解释“重启后恢复了什么”。具体阅读见 [会话与记忆](../architecture/sessions-and-memory/)和 [调度与目标](../architecture/schedules-and-goals/)。

其次是**投递与完成的距离**。调度交付到收件箱并没有自动证明业务完成；进程崩溃、重复投递和已入队消息都需要执行层继续处理。我的理解是，Personal Agent 的可靠性最终要落到产物检查、幂等与撤销，而不只是一张任务列表。

第三是**控制的执行位置**。权限预设、审批服务与操作系统后端各有职责。平台界面需要说明它改变了哪项策略，审计还应能回到具体动作，见 [权限与沙箱](../security/presets-approvals-and-sandbox/)。

## 这一轮还没有证明什么

默认未启用的 Memory MCP 不能当成已具备长期个人记忆；可加载扩展不能当成所有 Profile 都装好了完整能力；公开预览和可下载也不能替代实际运行评估。

这轮让我更清楚地看到，Harness 的价值与 Personal Agent 的成熟度可以分别研究。下一步我会通过一个可恢复、可排程的测试委托观察它们怎样衔接，而不是从功能名称直接判断能否长期受托。
