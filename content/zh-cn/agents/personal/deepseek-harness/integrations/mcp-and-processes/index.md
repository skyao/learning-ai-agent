## 接通协议不等于托管完整服务

Memory MCP 指南给出了一条很清楚的责任线：stdio 方式由桥接层启动子进程，并跟随插件生命周期；HTTP 方式要求上游服务已经运行。桥接层不负责替 HTTP 服务建立数据库、迁移数据或维持其可用性。

这对平台设计很有参考价值。我需要区分连接配置、服务部署、会话状态和后端数据四个对象；在界面中删除连接，只能先视为停止接入，不能据此声称后端个人记忆已被删除。

文档还说明桥接层会过滤部分环境凭证与 DSH 变量，但其他环境变量仍可能被继承。我的结论是应核对实际传入子进程的环境和显式配置，而不是将“有过滤”解释成“所有秘密都不会传递”。

下一步用测试服务记录启动、异常退出和插件卸载，再核查进程是否结束、工具目录是否更新。这里没有连接真实个人记忆或外部账号。
