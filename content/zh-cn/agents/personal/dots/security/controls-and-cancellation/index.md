## 文档中的控制范围

Custom Rules 可以表达独立行动、按明确请求行动、事先确认或交回用户等意图，但不授予工具访问，也不覆盖内置要求。文档还明确区分：Pause 停当前主任务；委派任务在 Activity 单独停止；周期任务在 Scheduled 另行取消。已发生的动作不会因停止而自动撤销。[控制文档](https://learn.chatgpt.com/docs/dots/controls)

## 我的理解：停止操作需要明确作用对象

长期代理可能同时有主任务、委派任务、保存的计划和已发出的外部动作。如果界面只提供一个“暂停”，用户很容易把它理解成所有工作都已停止，而运行系统实际只改变了其中一层。

我想把停止的效果放到执行链中观察：不再产生新任务、取消队列中的动作、请求运行中任务结束，以及处理已完成的副作用。这些需要不同机制，不能从一个按钮名推出全部语义。

| 我准备检查的对象 | 对应问题 |
| --- | --- |
| 主任务 | 暂停后是否还产生新的委派？ |
| 已委派任务 | 收到停止请求前后，哪些动作仍可能发生？ |
| 周期计划 | 当前一次停止后，下一次是否仍会触发？ |
| 外部动作 | 已提交结果如何核对，是否存在可行补偿？ |

这不是 Dots 已确认的状态机，是我的后续验证框架。

## 规则与访问许可也要分别观察

用户允许某类动作，并不能代替插件授权或设备访问。反过来，工具具备访问能力，也不能自动证明当前任务获准使用它。

我会进一步看批准对象的稳定性：草稿、收件人或条件发生变化后，原有批准还覆盖到哪里？本轮只有文档说明，尚无运行记录验证这些边界。
